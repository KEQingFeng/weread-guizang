# 归藏 · 架构与模块地图

这份文件回答「代码在哪、谁调谁、数据落在哪」。要改哪一层，先看这一份；
要遵守什么规矩，看同目录的 `开发规范.md`；装与跑看 `部署说明.md`；
接手这一轮的变化看 `交接说明.md`。

事实以 1.2.2 为准，行号会漂，函数名不会。

## 1. 全局形状

```
      浏览器界面  ui.html  （单文件，原生 JS/CSS，无构建）
            │  fetch /api/*  +  轮询 /api/state (2.6s) 与 /api/log
            ▼
   本地后端  ui_server.py  （只监听 127.0.0.1，标准库 ThreadingHTTPServer）
            │
            ├─ 同进程：书架/笔记/导图/画板/小结/便签/导出/阅读统计/云同步/小助手/订阅/写作/时长账/个人资料/安娜的档案的本地账/阅读计划 → 直接 import 各模块
            ├─ 子进程：取书、登录、加书架、装组件、剪藏、视频转笔记、安娜的档案窗口 → py() + script(name)，cwd = 数据目录
            └─ HTTP：微信读书官方 Agent Gateway（用户自填 wrk- Key，只读）；安娜的档案站点
                     只由那个看得见的窗口去访问（用户自己浏览、自己登录，归藏不代抓）；
                     剪藏 / 订阅 / 视频侧只碰用户点名的源站
                     （知乎/小红书/X、各 RSS、B 站/YouTube）
            │
            ▼
      本机数据   cache/（配置、封面、索引、日志、feed.json、flomo/、tools/、activity.json、avatar.bin、
                readplan.json、anna.json、anna_cmd.json、anna_profile/、downloads/anna/）
                ＋  书库/<模块>/<书号>/（章节 md + 图 + 元数据，七种来源同一形状）

   两个入口包着同一套后端：
     · shell/  Swift 原生壳 → dist/归藏.app → 安装包/*.dmg（双击即用）
     · shell/windows/ + 启动归藏.bat  Windows 没有原生壳，入口是两个 .bat
       → 安装包/归藏-Windows-*.zip（解压即用：安装归藏.bat 复制到 %USERPROFILE%\归藏
         并建桌面快捷方式，启动归藏.bat 可原地跑）
     · mcp/    Node stdio 适配器 → 把 HTTP 包成 61 个 MCP 工具（十二类），给 AI Agent 用（skills/ 是说明书）
```

1.0.3 起这条链上多了一次**认人**：界面、两个启动脚本、壳、适配器问的都不是「8770 有没有人
答腔」，而是「答腔那个是哪份代码」（`ui_server.py` 字节的 sha1 前 12 位）。旧后端照样答，
以前就被当成「服务在跑」，于是新功能一律 404 —— 三条被点名的 bug 根因全在这。
判断只在 `platform_compat.port_verdict` 一处（`free / reuse / takeover / busy / stranger`），
四个入口按动作分派；界面那边对应 `GZ.code` + 页顶横幅 + `POST /api/restart`。

要点：后端是**唯一真源**。界面、壳、MCP 三种入口共用同一份 `ui_server.py`，
所以「界面能干的，Agent 也能干」，反之加接口时三边同时受益。

1.0.5 起多了一整块**写作平台**（`writer.py`）：稿子是书库第七格 `写作/write_<12hex>/`
里的一本书（`draft.md` 是真相，`meta.json` 存版本号与快照索引，`versions/` 留最近 30 份），
所以「写作」不是外挂的一棵树，它跟别的内容一样住在书库里。同轮还加了两个小模块：
`activity.py`（学习 / 写作两张热力图的时长账）与 `person.py`（头像与本机简介）。
三者都由 `ui_server.py` 直接 import，不进子进程。

稿子之上还有一层**书 → 章**：册账是那一格里唯一的 `_books.json`（`bk_<12hex>` 一本书，
`chapters` 存一串 `write_` 书号与顺序），**没有新的目录、也没有把正文搬走** —— 一章还
是原来那篇稿子，归册只是往账上添一个号。所以删书只是把账散开、一篇稿都不删；
界面、MCP、导出三条口读的都是这一本账。

0.9.9 之后取内容的通路从一条变成四条（取书 / 剪藏 / 订阅 / 视频），
它们唯一的共同点是**最后都落成一本形状相同的书**；中间过程各走各的，
合并在「落成书」这一步，而不是硬塞进同一个解析器。

1.0.6 加了一条**陪伴阅读**的线：

- `readplan.py` → 每本书的阅读计划。纯逻辑（进出都是 dict，不看时钟、不碰磁盘），
  页数按正文字数折算、进度取只增不减的高水位、读完留档；落盘与加锁在 `ui_server.py`，
  账本在 `cache/readplan.json`。因为它是纯函数，没起服务也整套测得了。

同轮砍掉了主页的 Agent 气泡与任务收纳栏（取书状态那条加载条就地给「详情」），
并把侧边栏从「指针划过就切页」改成「点一下才切页」。

1.0.7 把 1.0.6 的 Z-Library 整条通路删了（`zlib_client.py` / `zlib_login.py` /
`/api/zlib` / 搜书页右栏 / 三个设置项 / 三套测试全部移除，搜书改回只有微信读书一栏），
换进来的是**安娜的档案**这一栏，两个新文件、一进程内一子进程：

- `anna_state.py` → 这一路的本地账与规则：账本读写（`cache/anna.json`，原子写）、
  搜书口令（`cache/anna_cmd.json`）、下载夹路径、格式白名单与文件头识别（`classify`）、
  按字节摘要去重（`digest` / `mark_seen`）、域名清洗（`clean_domain` / `with_scheme`）、
  代理探测（`proxy_url`）、以及把一份下载转成书的 `ingest()`。全标准库，可离线单测。
- `anna_browser.py` → 那个看得见的窗口（子进程任务）。`launch_persistent_context(headless=False)`
  起 Chromium，profile 落 `cache/anna_profile/`，`downloads_path` 指进 `cache/downloads/anna/`；
  一边让用户自己浏览登录下载，一边泵 download 事件接住文件转成书、轮询口令条执行搜索。
  **它不读 cookie、不代填账号**，兜底 4 小时一定收摊。

它同样**不是第五条通路**：`ingest()` 走的是现成那条 `book_import.import_book`
（前缀 `anna_` 归「本地书架」那一格），书库的分格与形状一个没动。

## 3. 十三条主链路

**取书（长任务，分钟到小时级）**

```
界面点「取书」→ POST /api/action {action:"export", book:<id 或链接>}
  → extract_book_id() 从链接里抠书号
  → start_task("export", [py(), script("export_precise.py"), book_id], book=book_id)
      · cwd = DATA_DIR，env GUIZANG_OUTPUT = OUT_DIR   （引擎里的 output/ 就是这么落对地方的）
  → 引擎逐行输出 → _reader() 线程：抓「📖 书名 — 作者」与「全书导出完成」，同时 log() 进内存环形日志
  → 界面每 2.6s 轮 /api/state 看 task.running，每 1.2s 重画进度；日志用 /api/log?tail=N
中止：POST {action:"stop"} → stop_task() → pc.send_stop()（POSIX SIGTERM / Windows CTRL_BREAK）
      引擎收到后把手上那一章攒完再落盘；60s 内没退才 pc.hard_kill()
清掉重取：{action:"export.fresh"} → 先确认没有任务在跑，再 reset_book_output()，然后起新任务
      （顺序反了就会留下「书被清空 + 任务没起来」的最坏局面）
```

`done` 只在看到「全书导出完成」那行才置位，中止永远显示为「取到一半」——
0.9.8 那道谎就是这么修的。前端另按「已取章数 / 目录总章数」复核一次，两边都说齐了才算齐。

**安娜的档案（导航最后一格，1.0.7 起）**

```
POST /api/action {action:"anna.open"}
  → start_task("anna_browser", [py(), script("anna_browser.py")])：起一个**看得见**的
    Chromium 窗口（headless=False 是正确性要求，站点在 TLS 层挡机器请求），
    persistent context 落 cache/anna_profile/，downloads_path 指进 cache/downloads/anna/。
    窗口那头自己接本机代理（anna_state.proxy_url）。

POST /api/anna {mode:"search"|"domain"|"collect"|"clear"|"listing"}
  → search：只写一条口令到 cache/anna_cmd.json，窗口下一轮轮询看到就去搜。
      搜索参数名钉死是 q（term 打不通）；窗口没开时口令照样存，界面如实说
      「点了打开窗口就会搜这个」。
  → domain：clean_domain 把用户填的串削成主机名并强制 https，记进账本。
  → collect：补收 —— 把下载格里窗口没来得及转的文件再过一遍 anna_state.ingest，
      只读那一格，不碰用户放别处的文件；同名/同摘要的不重复入库。
  → clear：只清这一路的账（caught/imported/skipped/seen/books/pending），
      原文件与已入库的书一本不动。
  → listing：列下载格里现在有什么。
```

下载入库不在这段接口里：`anna_browser.handle_download()` 在窗口进程内接住 download 事件、
落盘、`classify()` 认格式，能收的直接 `anna_state.ingest()` 转成「本地书架」那一格的书；
所以界面看到的是一条条记录，而不是「任务进度」。

**页内读（不进浏览器也能读）**

```
GET /api/read?book=<id>            → 左栏目录（book_outline）
GET /api/read?book=<id>&ch=<文件>  → 该章正文（不给 ch 就是目录）
GET /api/md /api/img               → 单章源文与图片直读
右栏「边读边记」→ /api/mynotes（这本书的 notes.json）
                → /api/mynotes/export、/api/note_tpl、思维导图 /api/mynotes/map
正文渲染用 vendor/ 里的 markdown-it，不连 CDN。
```

**每本书的阅读计划（详情页定 / 改 / 结束，阅读器底栏实时读数）**

```
GET  /api/plan?book=<id>          → 这本的读数（没计划回 {has:false}）：总页数 / 已读 / 还剩 /
                                    今日与本周读了多少 / 达标没有 / ETA / 在不在轨上 / 往期档案
POST /api/plan {act:"set"|"pos"|"clear", book:<id>, …}
  → set：定或改。总页数由书本目录现算（readplan.total_pages），period 是 daily|weekly，
      可带 target 终点日；改计划保留已读高水位与已有的每日账（换目标不等于「今天白读」）。
  → pos：记一次读到哪（at 章 + frac 章内位置），页数由目录现算；**只增不减** ——
      位置往回了不动高水位，所以今日 / 本周的账只在真往前读时增长。读到尾声自动置 done_at
      并把当时的目标与起止日期存进 history（改新计划也冲不掉）。
  → clear：结束这本的计划（档案里已有的记录留着）。
  页数锚在正文（PAGE_CHARS 每 1000 字一页），跟字号、窗口宽窄无关 —— 同一本书今天明天
  是同一个数，「还剩多少页」才不会变成每天在变的空话。这一层是纯逻辑，
  落盘与加锁在 ui_server.py（plan_tick），账本 cache/readplan.json。
```

**剪藏（含知乎 / 小红书 / X）**

```
POST /api/clip {urls:[…]}（一次最多 20 条）
  → 按 host 分流：知乎 / 小红书 / X 走 web_parse，其余（尤其公众号）走 clip_article
  → 抓到正文 → 一本 clip_<id> 书入库 → 书架里当普通书读、导 EPUB/PDF
拿不到就如实报错：三家未登录时常只回「安全验证」页，这里认出来就说不成，不绕过登录态。

入口（1.2.0 起）：屏顶不再放常驻粘贴框，只留一颗手指圆钮 #cPick。
  点一下 → navigator.clipboard.readText() → clipSync() 填链接 → clipRunAll('preview') 自动解析
  → 外圈 r=33 的 SVG 环（cf-track / cf-bar）用 stroke-dashoffset 做进度，14s 慢慢走到 92%，
     收尾 clipRingDone() 在 .35s 内补满（完成正好一圈）→ sheet 弹「解析已完成」，文章在下方列表。
  读不到剪贴板 → clipPasteFallback() 弹层手动粘（常驻的位置只留给手指按钮）。
```

**便签富文本（1.2.0 起）**

```
左栏随手记那支笔换成 contenteditable 富文本区 + #fmBar 工具条（data-do：粗/斜/小标题/列表/引用/行内码）
  → 存盘 fmDraftMd() 用写作页同一把尺 wrGet(root) 把 DOM 转回 Markdown（wrGet 因此加了可选参数）
  → fmCopyHandler 把 text/plain 换成 Markdown；fmPasteHandler 认出 Markdown 就用 wrParse 渲回富文本
  → 卡片「复制」fmCopyMd(m) 把整条 m.md 原样放上剪贴板
```

**视频左栏「转写中」占位（1.2.0 起）**

renderVideoShelf() 在 running video 时于左栏顶部插 .vtbook.pending「转写中」行
  → 状态存 VID_PENDING_KEY（vidPendingSet / Get / Clear），刷新后仍在，vidFinish() 撤掉

**内置浏览器（外站由本机取回重送，1.1.0 第二轮起）**

```
顶端正中「AI 导航」(#aiNavBtn) / 安娜那一栏「内置浏览器」 /
「视频转笔记」顶部右侧「哔哩哔哩 / YouTube」(名册 `VT_PORTALS`，Issue #118) → openBrowse(url)
  → 界面切到常驻视图 viewPane('browse', …)，iframe#bzFrame 指到 /api/browse?url=…
  → GET /api/browse → web_browse.browse()：
      · normalize 只认 http/https，本机 / 内网黑名单复用 clip_article.BLOCKED_HOSTS → 拒
      · urllib 取回（UA 与剪藏同一份，超时 20s、>4MB 拒）；只取回应正文、由本机重新送，
        原站那几条挡嵌入的响应头不再带走；prepare() 摘掉原站 CSP meta、补 <base>，
        末尾接一段「点链接 → postMessage」的脚本
      · 非网页（图片 / PDF）按字节透传，让内核自己渲染
      · YouTube 那一站原样重送是一屏空白（1.2.1）：改由 yt_static 自己读那坨 ytInitialData
        铺一页静态目录，每支挂一颗「转成笔记」（data-gz-use → 界面 vidUseLink）
      · 1.2.2：认出 0 张卡时（未登录的首页 / feed 连那坨 JSON 里都不放内容），_yt_fill 按
        YT_LANDINGS 再取一处有货的落脚点，副标题换成 _YT_FILL_NOTE
  ← 界面收到 iframe 里 postMessage 的跳转 → 再取下一页（一页页在归藏里走，不跳去别的浏览器）
  · 那一行「正在取回这一页」(#bzLoad) 只在真去取一页时亮：iframe 的 load 一回来、或离开这一屏
    就收（`bzBusy()` 是唯一开关）；同一地址重进不再掀开它（issue #131：原来在 bzLoad 里无条件
    掀开，而同一地址又不重发 → 没有 load 事件来收，提示就永久压在后面的页面上）
取不回来 → error_page() 铺一页人话（地址不合法 / 内网被拦 / 超时 / 太大）
要登录、过验证的站点不走这一层：回退到安娜那种弹出窗口（会话留在浏览器档案里）。
```

**订阅（RSS）**

```
GET  /api/feed?mode=list|entries|entry|summary|groups|tags|settings|snapshots|refresh_status|opml
POST /api/feed {act:…}  —— 一屏订阅器的全部动作都走这一条，act 分发：
  → 源：discover / add / remove / reorder / refresh / refresh_status / refresh_stop
  → 组：group_create / group_rename / group_delete
  → 条目：mark / read_all / star(_toggle) / later(_toggle) / tag_add / tag_remove / tag_set / delete
  → 正文：fetch_content（只补没全文的，limit 兜住一次别打爆源站）/ fulltext（开关）
  → 收纳：shelf（单条入书架）/ prune（保留策略，先 dry_run 报数）/ snapshots / undo
  → 换格式：opml_write（先把文本摊开给人看）/ opml_import（同一份订第二遍不会重复）
  → add：给个网址即可，只给站点首页也行——discover 从 <link alternate> 挑最好的源
  → refresh：按源抓增量（ETag / Last-Modified），逐源隔离错误，一个坏了不拖垮其余
  → shelf：feed.to_shelf() → 一本 feed_<id> 书入库；全文够长直接用，只有摘要才回源抓正文
存储：cache/feed.json；不发请求的活（列、读、标、筛）都在进程内，刷新也只在被调用时发生。

```

**视频转笔记**

```

     → status 可用性（yt-dlp / ffmpeg / ASR 引擎 / LLM）· plan 认链接列分 P

**脑图与画板（边读边画，一切落在书目录里）**

     → 默认回 {doc, layout, forms, limits}：布局必须在后端算，前端再排一遍就是两份真相

     → save 收整份文档 → normalize + 上限裁剪（报出裁了几个）→ 算回布局 → 落 mindmap.json

形态是**文档的一部分**（`doc.form`），不是界面里的视图开关：只改界面状态的话，停手一秒半

存完与撤销 / 重做之后，界面都以磁盘上那份为准（`check_board_map_ui.py` 有这条硬断言）。

**AI 小结（一个入口，两种模式，四种内容）**

```

  → LLM 三项（url/key/model）从 config 读，没配就报「没配」，不编内容

**便签（flomo 那一条线：导入 → 时间线 → 收成书 → 画像）**

```

  → shelf 把一条收成一本 flomo_<id> 书，进「便签」那一格，之后跟别的内容一样读、一样记

（挨着的一条 /api/flomo 是反向的：把划线发去 flomo webhook，写的是用户的 flomo，
  这一条只动本机 —— 命名分开就是为了别让两边混）
```

**写作平台（AI 只搭手不代笔）**

```

  → 书与章那一层只有 `_books.json` 一本账：这几动作改的都是「哪几章、按什么顺序」，
      正文一个字节不碰；回话带 book_detail（或拆/合后的整份册账），界面不必再打一次清单
  → book.delete 只是把书散开、章退回「未归册」，一篇都不删（删稿子是另一个动作：
      `/api/action` 里的 `book.delete` 才是真删一本 write_… —— 两个名字撞了，差别在话术上）

POST /api/writer/ai {mode:"cont"|"spark"|"polish"}   —— 三件套，走用户自填的兼容 OpenAI 接口
  → cont 流式续写，长度四档（一句 / 一段 / 三个要点 / 写完这一节），上限与终止符由后端按档位定
  → spark 一次给 3 个方向，已给过的角度带回去避免重复（认 draft id 记账）
  → polish 只改选中的那一段：以 difflib 切成**逐块差异**交给人，人一块块接受，任何一步都不直接覆盖正文
素材原文只进提示词：日志、回执、界面上都不回显（落进日志就等于落进仓库）
GET  /api/writer/export?kind=png|pdf|epub|md   → 四样共用一份 HTML：图片/PDF 走随包 Chromium 渲染，

      → 给 id= 导一篇，给 book= 导整本合稿（按册账顺序拼，先落成临时目录再走同一条渲染路）
```

## 4. 数据落在哪

| 路径 | 装成 app | 源码直接跑 |
|---|---|---|
| 数据根 `DATA_DIR` | `~/Library/Application Support/归藏/` | 项目目录本身 |
| 书库 `OUT_DIR` | `~/Documents/归藏/` | `DATA_DIR/output/` |
| 虚拟环境 | `DATA_DIR/.venv/`（`platform_compat.venv_dir`） | 项目 `.venv/` |

`DATA_DIR/cache/` 里的东西：

| 文件 | 内容 |

| `config.json` | 微信读书 API Key、小助手地址/Key/模型、flomo webhook、导出目录偏好 |

一本书的目录（`书库/<模块文件夹>/<书号>/`）——**取回、导入、剪藏、订阅、视频、便签、写作七种来源都是这一套形状**，
所以阅读器、导出、定位文件都不用区分来源；模块文件夹由 `book_layout.DIR_OF` 定名，
1.0.1 启动时把散在书库根下的旧书按前缀归置进去（只搬不删）：

```
meta.json        title / author / done / source / chars / updated_at
                 非微信读书来源另有 format（local/clip/feed/video）与各自附加字段：
                 clip → url；feed → feed_id / feed_title / date；video → url / asr_engine / duration
_catalog.json    [{"chapterTitle": "第N章"}…]，长度＝总章数（进度分母）
chapters/0001.md 逐章正文（图文按阅读顺序交错）
raw/NNNN.json    每章一份：图片 URL 与 text_len（书架上的字数按它累加）
images/          正文图片
_progress.json   引擎实时进度（翻到第几页），一章内部进度条靠它
notes.json       归藏里的划线与批注 {schema, marks[], entries[]}；读坏先备份 .bad-<ts>
notes.md         笔记的 Markdown 导出（视频来源落书时一并生成）
mindmap.svg      按大纲画的思维导图（只读，`book_notes.py` 现算）
mindmap.json     用户自己画的那张可编辑脑图（`mindmap.py`，0.9.9 加）
                 —— 与上面那份名字不同、各写各的：手画的图被自动图冲掉是最不能接受的事故
boards/<id>.json 画板的画布（fabric.js 序列化，JSON 是真相，随时能再编辑）
boards/<id>.svg  画板导出物（能再编辑的那份）
boards/<id>.png  画板导出物（发给别人看的那份）
transcript.json  视频转写的段落与时间戳（编辑器改的就是它，0.9.9 加）
transcript.txt   它的纯文本视图（老书只有这一份，读时兜底）
exports/         转写导出物：srt / vtt / txt / md / json 五种扩展名，读的时候走白名单
```

**写作那一格形状不同**（它不是「书」而是「稿子」）：`写作/write_<12hex>/` 下是

```
draft.md         正文真源（没分章，整篇一份）
meta.json        title / rev（版本号）/ updated / history（快照索引）
versions/        最近 30 份快照（每 20 次存自动留一份，空转不加；回退前也会先留一份）
```

同一格的根上还躺着一个文件 `写作/_books.json`：册账
（`{"v":1,"books":[{id:"bk_<12hex>",title,chapters:[write_…按顺序]}]}`，原子写、读坏了给空表）。
**书不是目录**，章仍然是一个个 `write_…/`，所以这一层的增删改排序都不产生文件搬运；
`book_layout.migrate()` 只扫书库根、只搬「像一本书」的目录，那一格里的散文件它根本不看。

所以写作用的是 `writer.py` 一套读写口，不走 `book_notes` 那套读书笔记的路径 ——
两边的「存盘」语义不一样：书是逐章写、稿子是整篇覆盖 + 认 `rev`。

视频来源那本还会在落盘时把 `notes.md` / `mindmap.svg` 一并与书同目录写入；
四种非微信来源的 `format` 字段就是给书架分组用的，别拿 `source` 之外的东西判来源。

`reset_book_output()` 清残稿只删 `RESIDUE_DIRS`（`chapters/ raw/ images/`）与
`RESIDUE_FILES`（三本账本连同它们各自的固定 `.tmp`：`_catalog.json(.tmp)` / `_progress.json(.tmp)` / `_stuck.json(.tmp)`），再顺尾巴收掉这本书目录里「写到一半被强杀」留下的临时件（`drop_stray_tmps(d)`：`os.walk` 过 `boards` / `mindmaps` / `video` / `_ai`，以 `.tmp` 收尾的**普通文件**才删，符号链接与同名目录不碰，`meta.json` / `notes.json` 这些正式产物一个不动 —— 随机名那一族的半截件不进任何点名名单，只这么认），最后清书库根 / 模块文件夹上的合并稿（`drop_stray_md` 连改名之前被强杀留下的 `<书名>.md.tmp` 一起收 —— 那份半截件不以 `.md` 结尾，两本点名名单都指不到它，只跟着这本书走）；`meta.json`、
`notes.json`、`mindmap.json`、`boards/`、`transcript.*` 都不在里面 —— 取书失败不该让人
连带丢笔记、丢图、丢画，「清掉重取」同理。往这两个元组里加东西之前先想清这一点。

## 5. 两套 id，别混

| 名字 | 形状 | 用在哪 |
|---|---|---|
| 阅读器 id | 18–24 位字母数字混合，来自 `deepLink` 里的 `v=` | **本地目录名**、`/api/*` 的 `book=` |
| 书架 bookId | 书城短号（纯数字 5–20 位，判定只在 `book_ids.py` 一处），`/shelf/sync` 每条里的 `bookId` | 官方只读接口（`/book/info`、`/book/getprogress`…）、`shelf_add` |

从详情页、划线搜索、书城搜索进来的常常是后者。传错命名空间不会报错，只会**装作没有**：
`book_id_pairs()` 的注释写着「明明有划线却说没有」，`/api/detail` 会把已抓取的书
显示成「尚未抓取」——这类静默错乱比抛异常难查得多。
处理办法是后端自己换算：`store_to_reader_map()` :1388 拉一次 `/shelf/sync`，
用 `deepLink` 里的 `v=` 建「bookId → 阅读器 id」映射，缓存 10 分钟，失败用旧值；
`book_id_pairs()` :637 则两个方向都试。前端传来的字符串一律先过 `extract_book_id()`。

本地来源带前缀区分，一本书属于哪条通路看前缀就够：
`imp_<名>` ＝ 自己导入，`clip_<名>` ＝ 剪藏（含知乎/小红书/X），
`feed_<名>` ＝ 订阅条目，`video_<名>` ＝ 视频转笔记，`flomo_<名>` ＝ 便签收成的书，
`anna_<名>` ＝ 安娜的档案窗口里下回来的（前缀归 `local`，落「本地书架」那一格，不新开格），

它们的分支多、又都要自己兜住异常，塞进 `_dispatch` 会让那一层的 try 兜底看不清边界。

新增动作优先加进 `_dispatch()` 而不是开新路由：那一层的兜底把异常收成一句人话，消息口径
也统一；自己开路由要自己决定「这一步失败了用户看见什么」。1.2.1 之后 `Handler` 最外面还加了
一层总兜底（`handle_one_request`）：任何一条路由漏接的异常都收成 200 + 「这个操作没做成」
并往日志里留下是哪条路由、什么异常，不再让 `http.server` 默默把连接掐断；已经回过话的
（含流式那一族，靠 `_sent_response` 判）不追尾，接住之后主动断连。所以「开新路由」不必再
手写那层防掐断的 try，但局部退路仍然要自己定 —— 总兜底只保证不静默失败，不保证那句话对
用户有用。`_action` 那层由 `tests/test_server_fallback.py` 守着，最外面这层由
`tests/check_post_guard.py` 守着。

## 7. 前端（ui.html 一个文件，约 20 千行，没有构建步骤）

- 结构：视图面板 `.vpane` 常驻 DOM，切视图只改 class 与属性，**不整块重建**
  （重建会「点一下闪一下」，第 29–30 项修的根因）。`[hidden]` 与 class 两套都要留意。
- **每一屏脚下是同一块舞台**（1.1.0 第二轮）：`main` 的 `max-width` 只认 `--main-w`
  （`min(1440px,100%)`，全站一处定义），不再按页给 `main` 另开宽度，`html` 常驻
  `scrollbar-gutter:stable`，所以侧边栏与整页左右边不会随页面横跳。
- **内置浏览器是一整屏常驻视图**：`viewPane('browse', …)` 里一个地址栏 + `#bzFrame`
  iframe，顶端正中「AI 导航」（`#aiNavBtn`）从 `openBrowse()` 进；iframe 里 `postMessage`
  回来的跳转由父页面接住再取下一页（`sandbox` 让外站脚本读不到界面）。那一行「正在取回这一页」
  （`#bzLoad`）只在真去取时亮，取回或离开这一屏就收（`bzBusy()` 一处开关，issue #131）。
  1.2.1 起「安娜的档案」
  那一栏不再挂这个入口，只留搜索框 + 搜索键（窗口由后端 `anna_browser` 领起来）。
- **控件反馈底座收在一处**（1.2.1 · R4-5）：`ui.html` 顶部一块 CSS 令牌（`--fx-fast / --fx-dur /
  --fx-slow / --fx-out / --press`）+ `:where()` 压权重的通用按压 / `:focus-visible` 焦点环 +
  `.tapfx` 落点涟漪 + `.fx-in` / `.fx-pop` 动画；JS 侧是委托的 `tapfx` / `fxIn()` / `fxPop()`
  （见文件末尾「交互动效底座」那段）。新增控件直接引用令牌与这几个类，别再各写一套，
  也别让反馈碰宽高边距（`check_ui_polish.py` 守着）。
- **本机请求一律走 `gzApi(path, body, ms)`**（`ui.html:4629`），不要裸 `fetch` +
  `.catch(() => null)`。它永远回一个对象、不抛异常，并把失败分成四种真相：
  `down`（连不上）/ `stale`（后端认不得这条接口，多半比界面旧）/ `http`（回了 5xx，
  带后端原话）/ `bad`（回了话但读不懂）。四种揉成一种就只能说一句假话，
  而假话会把人带去查一件本来没事的事。
- **`GZ` 是前后端关系的状态**（`ui.html:4547`）：每次 `/api/state` 轮询把后端的
  `version` / `code` 记进来，与 `GUIZANG_PAGE` 对不上就置 `GZ.stale` 并挂页顶横幅 `#swapbar`；
  「换新后端」走 `gzSwapGo()`，成功则 `gzWaitBack()` 认指纹变化自己刷新页面。
  `GZ.why` 是用户点过之后后端给的那句原因，**粘在横幅上**直到用户点掉或版本对上，
  否则会被下一次轮询盖回去。`GZ.swapping` 期间横幅不抢话。
- 冷启动的屏：`render*View` 先铺与真实结构同形的骨架（`skelLines` / `skelRows` /
  `skelCards` / `skelStats`），数据到了才换真内容；`pane.dataset.sig` 挡住同数据重铺。
  悬停预取三件套 `prefetch` / `preAwait` / `hoverAhead`（`PRE_TTL` 10s、`PRE_DWELL` 90ms）。
- 玻璃层是数得清的：开合浮层（`.rdpop` / `.ntlay` / `.veil` / `.pop` …）用 `visibility`
  门控，收起来就不参与合成；纸面（`--paper` 一族）是实心色，故意不吃磨砂滑杆。
- 阅读器状态 `RD`：`{book, chapters, at, ol, olAt, olReady, resumeCh, resumeY, back}`。
  读到「哪一章 + 页内第几行」落在本机 `localStorage` 的 `guizang-readpos-<book>`，
  停手 800ms 才写，开书回到那一行、那一笔偏移只用一次；本章大纲（`rdOutline` /
  `rdOlMeasure` / `rdOlActive`）只在打开浮窗那一刻量一次各节偏移，之后滚动只比数字。
  笔记状态另在 `NT`，划线笔记里「条目」那一份 Markdown 编辑器在 `NTED`，写作平台整屏在 `WR`。
- **写作那一屏有两套「Markdown ⇄ 界面」的脑子，必须说同一种语言**：磁盘上仍然是 `draft.md`，
  屏幕上是一块 contenteditable（`#wrTextIn`），中间那对翻译在 `WRE` —— **每条正则都逐条对着
  `book_export.md_to_html` 抄，改一边必须改另一边**，否则后果很具体：编辑时看着对，导出全变样。
  语法集合就是工具条 `WR_TOOLS` 会写的那几种，不追求 CommonMark 全量；用户手打的井号、星号
  在稿子里存成反斜杠开头（两边都认这份转义），「这个字」和「这个记号」从此分得开。
  两条硬约束记在这里：系统自带的浏览器内核解析到 `(?<!` 会让**整段脚本**报语法错、全屏失效，
  所以斜体那条不抄后视断言，用回调看左右邻居判（`wrInline`）；色板、填链接、表格矩阵那些浮层
  一律 `pop.onmousedown = ev => ev.preventDefault()`，否则选区先被这一下清掉，
  颜色就涂到光标那一个字上（`WR.range` 存的就是点工具条之前用户选到哪儿）。

     也不挂在 `window` 上，探针要用裸名字 + `typeof` 兜底。

| `skills/` | `guizang`（用自然语言操作归藏）与 `book-speedrun`（把一本书讲透） | 只写「先查状态再动手、写操作只做用户点名的那个」这类判断，不重复工具参数 |

## 10. 加一个功能的最短路径

1. 想清它属于哪个模块。新的独立能力就照 `clip_article.py` 的样子单开一个文件，
   开头写清「为什么单独一个文件」；否则并进已有模块的对应函数群。
2. 后端：写函数 → 在 `_dispatch()` 或 `do_GET`/`do_POST` 挂上 → 返回 `{ok, msg, …}`，
   `msg` 给人看，失败也要是人话。
3. 前端：`ui.html` 里加控件与调用；只改属性不重建视图；文案对齐现有措辞；零 emoji。
4. **进包清单**：新文件补进 `shell/build_macos.sh` 的 `APP_FILES` / `APP_DIRS`。
   漏了 = 源码跑一切正常、装成 app 一点就哑，而这正是本仓库唯一没法在本机
   用户视角复现的路径。源码包会从同一份清单派生，不用两处改。
5. 测试：能在进程内测的写 `tests/test_*.py`；要点才的写 `tests/check_*.py`
   （从 `selftest` 取路径、夹具 `atexit` 自清），并加进 `tests/run_all.sh`。
6. `bash tests/run_all.sh` 全绿 → README 的功能清单与本文件同步（新增模块要在 §2
   表里有一行、§6 接口面里有一路）→ `docs/交接说明.md` 补这一轮改了什么、还差什么、
   `docs/开发规范.md` 补这一轮新立的规矩 → 展示图用 `.venv/bin/python tools/shot_pages.py`
   重拍（无头 Chromium + 沙盒假书，落 `docs/shots/`）→
   按 `开发规范.md` §8 发版：版本号改 `ui_server.py` 的 `VERSION` 与 `ui.html` 的
   `GUIZANG_PAGE` **两处**（成对，静态门里 `check_route_pair.py` 守着），
   界面「关于」、`.app` 的 Info.plist、`dmg` 的文件名都从 `VERSION` 取。
   **新增界面会调的 `/api/...`，先补后端路由再写前端** —— 反了会被同一项抓红。

**如果新功能是「又一条取内容的通路」**：照 `feed.py` / `video_note.py` 的样子单开文件，
让它最终落成一本形状相同的书（`meta.json` + `chapters/` + `raw/`），
在 `_dispatch` 之外单开一个 `*_view` / `*_do` 路由，
并把来源前缀注册进 `safe_book_dir()` 与书架的来源分组。别去改通用解析器。

## 11. 已知的边界（别当成已完成）

- Windows 只做到「脚本与平台分支齐了、单测假跑过」，**没有出 .exe，也没有真机验证**。
- **换班这条路径的边界要说清**：`tests/test_backend_identity.py` 里那个「旧后端」是系统临时
  目录里现编的（脚本名必须叫 `ui_server.py`，因为 `is_our_backend` 认的就是这个名字），
  端口、回执、交接都是真的，但**没在真装过 `.app` 的机器上跑过一次「装的那版被源码版接管」**
  —— 壳里的进程由 LaunchServices 拉起，命令行可能与夹具不同。`.bat` 与 `netstat` /
  `Get-CimInstance` 那两段同理，本机只有 macOS。护栏的方向是保守的（认不出是谁就不动、
  任务在跑就不动），所以判不准时的后果是「该接管没接管」，不是误杀别人的进程。
- 页顶横幅与 `gzApi` 那套只在 Chromium 上实测过；Safari 下的 `AbortController` + `fetch`
  行为没验过（本机界面默认用系统浏览器打开）。
- `.app` 未做签名与公证：首次打开要右键「打开」，`dmg` 里那份说明是给这一步的。
- 取书依赖微信读书网页阅读器的渲染方式（正文画在 Canvas，所以 Hook `fillText`）。
  对方改版就可能整片失效，这类失效在界面上表现为「抓不到正文」而不是报错。
- EPUB 是标准库手搓的，`mimetype` 必须是 zip 首个条目且 STORED —— 动它之前先读
  `book_export.py` 开头那段；未在各类阅读器做过全面兼容矩阵。
- 划线/进度等只读数据全部依赖用户自填的 `wrk-` Key 与本机登录态；
  `wr_skey` 过期会表现为「加书架失败」，处理是 `shelf_add.renew_session()`。
- 阅读到的**行级位置**只存在本机 `localStorage`（`guizang-readpos-<book>`），
  换浏览器、换机器、清站点数据都会掉，退回「记住上次读到第几章」那一层。
  它不参与云同步 —— 云同步走的是账号侧的阅读时长与笔记文件。
- 本章大纲只到 `h1~h3`、每章封顶 200 条（`ui.html` 里 `querySelectorAll('h1,h2,h3')`
  之后 `slice(0, 200)`）：60 条太抠，一本讲义体的书一章里能有一百多个小标题。
  再深的层级属于正文结构问题，不是导航问题。
- 脑图四形态的坐标是后端算的，上限也卡在后端（400 节点 / 8 层 / 200 条边）：
  超了就裁，裁掉的数量累计进 `dropped` 如实报出，静默吞掉等于骗用户（他会以为
  备注还在）。连线只认节点 `id`，两端有一个不在图里这条线就被丢掉并计数 ——
  半截的线和自环画出来都只会让用户以为图坏了。
- 画板的真相是 `<书目录>/boards/<id>.json`，SVG / PNG 只是导出物。后端**不解析画布**：
  `canvas` 只要求是个对象，不是对象就换成空画布 —— fabric 的版本、对象、路径随它去。
  代价是画布内容写坏了后端不会报，只有前端加载时才画不出来，所以覆盖前留一份 `.prev`。
  一本书最多 200 块，单块 6 MB JSON / 8 MB SVG / 25 MB PNG —— 体积闸防的是「一块板
  吃穿磁盘」，不是给用户当预算用。`vendor/fabric.min.js` 随包，**不连 CDN**：
  断网也能画，代价是升级 fabric 要手动换那一个文件。
- 转写是「整本覆盖」的接口：前端存之前一定回后端取一次无筛法的全量、把待存改动按
  `id` 合上去再写回（戴着筛子保存会把没匹配上的段落整批抹掉）；后端那边收到空列表
  直接拒绝写盘，`after` 这类编辑器内部锚点落盘前吃掉。这条护栏在进程内测不到 ——
  筛子和待存队列都在前端，**只有真机能验到磁盘**。
- 全文搜索没有做（`/api/notes_search` 搜的是划线与想法，不是书本正文）。
- 知乎 / 小红书 / X 的解析依赖对方「现在」怎么发页面，随时可能失效。未登录时
  知乎与小红书多数情况只回验证页——这是平台限制，**不做登录态绕过**也就没有
  cookie 上传问题；失效时如实报错，别把它改成静默失败。
- RSS 的已读 / 收藏 / 稍后读 / 标签都是**本机口径**：不与任何账号侧服务双向同步，
  没有后台线程也没有定时器 —— 刷新只在被调用时发生（界面那个 900ms 轮询问的是
  「抓到哪了」，不是「该不该抓」；要新内容得点刷新）。`cache/feed.json` 是唯一存储，
  整份读改写的链条不原子，所以改盘动作全进一把可重入锁：后台刷新的几十秒里用户点的
  已读 / 标签 / 删除不能被这一轮抓完的整份覆盖冲掉（实测复现过，`check_feed_ui.py` 守着）。
- 视频这条线只支持 B 站与 YouTube；转写自 1.0.8 起**只走云端**（用户填的兼容 OpenAI
  `/audio/transcriptions`），专有名词 / 多人对话 / 强口音不保证 —— 准确度取决于他选的那个模型。
  本机不装引擎、不下权重；`media_setup.py` 与 mlx / faster 那套已整体删除，别把本地路径加回来。
- `yt-dlp` 属于「随平台改版天天要更新」的工具：视频取不到时先
  `.venv/bin/pip install -U yt-dlp` 再试。这条不是 bug，是这类工具的性质。
- `bootstrap.py` 的依赖门禁只列 `playwright, genanki, pypdf, feedparser, yt_dlp` 五项；
  ffmpeg 由它第四步按需下（macOS 静态版），转写不再需要任何本机模型。
- 视频任务的真跑链路（真下载 + 真转写）只在 `GUIZANG_VIDEO_LIVE=1` 时跑，
  默认门禁是离线夹具；也就是说**喉咙那一段没有被日常门禁覆盖**，改它要另跑一次真链路。
- 写作的 AI 三件套（续写 / 灵感 / 润色）依赖用户自填的兼容 OpenAI 接口，**未对具体厂商逐一联调**；
  接口缺席时按钮如实说没配，不产生假内容。稿子的 PNG / PDF 导出走随包 Chromium 渲染，
  **未在各类阅读器/看图软件做过兼容矩阵**；EPUB 与 Markdown 由标准库直接写出。
- 两张热力图（学习 / 写作时长）靠界面心跳上报：学习时长 = 应用在后台运行的累计秒数，
  写作时长 = 停在写作页的累计秒数。**没有在长时间挂机场景下核过对**——单 tick 封顶 300 秒、
  单日封顶 12 小时只是防「一天记成 24h」的兜底，不等于真实口径已被验证。
- 安娜的档案这一栏是「把窗口交给用户」，不是「接口取书」，**能力边界在对方站点上**：
  域名轮换（2026-10-07 实测只有 `annas-archive.is` 有响应，`.gd` 给 502、`.org`/`.se` 连不上）、
  下载要先登录（每个下载链接都跳 `/account`）、页面带 `X-Frame-Options: SAMEORIGIN` 所以嵌不进来、
  对方 WAF 在 TLS 层挡机器请求（无头与 `urllib` 被 307→513 顶回来，所以 `headless=False` 是正确性
  要求）。这几条都不是本工具能兜住的，失效时如实报错，别改成静默失败。
  真下载那一段只在**沙盒与本机夹具**上端到端跑过（接住 → 落盘 → 转书 → 上架），
  **没有在用户自己的真账号上走过一遍**。
- 阅读计划的一页 ＝ 1000 个正文字符，是**折算口径**，跟屏幕上的一页不是一个东西（见
  `docs/部署说明.md` §11）。进度取只增不减的高水位：往回翻不记账。到期日（ETA）按
  本机时钟与本机累计进度算，换机器、清数据都会重来。
