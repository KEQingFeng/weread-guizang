# 归藏 · 部署说明

本地微信读书工具。取书（导出 Markdown + 插图）、书架与笔记管理、AI Agent 接入，三件事都在本机完成，不经第三方服务器。界面与 MCP 都还接了剪藏、订阅、视频转笔记，以及把 flomo 导出的便签收进同一个书架。

## 一、目录内容

| 文件 | 作用 |
| --- | --- |
| `export_precise.py` | 抓取引擎。Playwright 驱动 Chromium，hook Canvas 的 `fillText` 取正文；按「正文里出现的目录标题」分章；每轮翻页有硬超时，支持断点续传；结束时自己写 `meta.json` 的完成标记 |
| `download_images.py` | 插图并发下载（强制 IPv4——macOS 上 urllib 先试 IPv6，路由不通每张图要卡约 120 秒） |
| `login.py` | 登录与登录态检测（以 `wr_vid` cookie 判定，不是看 URL）。扫码窗口被关掉就立刻收工，不干等满 5 分钟 |
| `shelf_add.py` | 把书加进微信读书书架（写操作）。官方 Agent Gateway 只读，所以复用 `cache/browser_profile` 的登录态调网页端 `/mp/shelf/addToShelf`；stdout 输出一行 JSON 给后端 |
| `platform_compat.py` | 平台差异集中处（Windows / macOS / Linux）：解释器路径、Playwright 浏览器缓存目录、**系统代理转环境变量**（playwright 的下载器是 Node，不读系统代理，只认 `HTTP(S)_PROXY`）、子进程建组与中止、结束进程树、清残留浏览器、打开文件管理器。业务代码只调它，不各写一份 |
| `ui_server.py` | 本地后端，标准库实现，仅监听 `127.0.0.1`。含官方网关代理、封面缓存、笔记索引、Anki 卡包生成、flomo 转发、链接解析、写作稿件的读写与版本、学习/写作时长账、个人资料（头像 / 简介 / 导航布局）、Z-Library 取书（登录 / 搜书 / 下载入库）与阅读计划账；书架账本按七个模块各分一格（夹子 / 排序 / 状态 / 标签互不串门） |
| `book_layout.py` | 书库目录结构与「书号 → 哪一格」的唯一算法：模块清单、来源前缀、落盘路径、老目录归置（只搬不覆盖）。后端、界面、打包都读它，所以单独一个文件 |
| `ai_sum.py` | AI 小结：一个入口、两种模式（学习理解 / 归纳）、三种内容（读书只吃当前章，剪藏与视频全文）。范围怎么算、超长怎么掐、回得不像导图时怎么兜、一个模式一份缓存，全在这里 |
| `flomo_notes.py` | 便签（flomo）那条线：读导出包、一条笔记收成一本形状相同的书、标签那把尺、记忆画像（只由数字与标签算出，不含笔记原文） |
| `writer.py` | 写作平台：一篇稿子落成书库第七格里的一本书（`draft.md` 是唯一真源，带 `rev` 的存盘、`versions/` 快照），外加 AI 三件套（续写 / 灵感 / 润色）与四种格式、四套模板的导出 |
| `activity.py` | 学习 / 写作两张热力图的数据层：心跳（单次夹 300 秒）、单日封顶、缺日补零、连续天数。纯函数，不算盘不碰 HTTP |
| `person.py` | 个人资料：头像（按魔数认 PNG/JPEG/GIF/WEBP）、简介、名字。存 `cache/avatar.bin` 与 `config.json`，不进云同步、不进 git |
| `zlib_client.py` | Z-Library 取书（走安卓 App 那套 eAPI）：登录换令牌、搜书、取下载直链。只用标准库 `urllib`，代理复用平台那一套；凭据只落令牌（`cache/zlib.json`，权限 600），不存密码。只收 EPUB / PDF；下回来的书交给 `book_import` 落进「本地书架」 |
| `readplan.py` | 每本书的阅读计划：页数按正文字数折算（每 1000 字一页）、进度取只增不减的高水位、跨天 / 跨周记账、读完留档。纯逻辑，不碰磁盘也不看时钟（时间由调用方传），落盘在 `ui_server.py` |
| `ui.html` | 前端单文件。液态玻璃视觉、日夜主题、自定义壁纸（文字颜色随壁纸明暗自适应）、书架/详情/笔记/统计/推荐/**搜书两栏**/订阅/视频/便签/写作各视图、个人主界面（头像、简介、两张热力图）、**阅读计划**那块、从左侧滑出的导航（点一下才切页）、批量操作、端内卡片回顾 |
| `mcp/guizang-mcp.mjs` | 零依赖 Node MCP 适配器（stdio + JSON-RPC 2.0），56 个工具（十一类），服务没起时会自己拉起来 |
| `tests/ui_check.py` | 布局校验脚本（真实视口量几何 + 抓 console 报错，可传地址） |
| `bootstrap.py` | 环境自举，分两段：前三步建虚拟环境 → 装依赖 → 装 Chromium（缺哪步补哪步，失败即停）；后两步装 ffmpeg 与转写引擎（**尽力而为，失败不拦门**——取书那条线不需要它们）。只用标准库，所以裸系统 Python 就能跑它。首启页的「我思故我在」调的就是它 |
| `shell/` | macOS 原生外壳（Swift + WKWebView）。`main.swift` 是外壳本体，`onboarding.html` 是首启页，`build_macos.sh` 打成 `.app`，`make_dmg.sh` 打成能发给别人的 dmg，`首次打开必读.txt` 是随包发给用户的那份说明，`Info.plist` 是包描述 |
| `tools/make_icon.py` | 用 CoreGraphics 画应用图标（蓝色圆角方块 + 摊开的书），不依赖素材文件 |
| `启动归藏.bat` | Windows 一键启动（双击即可）：没虚拟环境就自己建并装依赖，已在跑就直接开浏览器 |

## 二、从零跑起来

macOS / Linux：

```bash
cd <本目录>
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m playwright install chromium     # 约 368MB
.venv/bin/python ui_server.py --port 8770
```

Windows（PowerShell 或 CMD）：

```bat
cd /d <本目录>
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m playwright install chromium    :: 约 368MB
.venv\Scripts\python.exe ui_server.py --port 8770
```

浏览器打开 `http://127.0.0.1:8770`。`requirements.txt` 五项依赖：`playwright`（抓取引擎与图片/PDF 渲染）、`genanki`（导出 Anki 卡包）、`pypdf`（PDF 阅读与导出）、`feedparser`（订阅解析）、`yt-dlp`（视频取音频）；后端本身只用标准库。

Windows 上双击 `启动归藏.bat` 等于把上面四步一次做完（缺虚拟环境就自动建、自动装依赖），已在运行时再双击则直接开浏览器。

MCP 适配器需要本机有 Node（Windows 上 `node -v` 能出版本号即可）。

### macOS：打成一个双击即用的程序

上面那一串命令是给「要改代码」的人看的。如果你只是想在 Mac 上用它，可以让它变成
一个正经应用 —— 双击打开，不用开终端：

```bash
./shell/build_macos.sh          # 产出 dist/归藏.app（约 3.6MB）
```

把 `dist/归藏.app` 拖进「应用程序」就装好了。整个过程不需要完整 Xcode，用
CommandLineTools 自带的 Swift 就能编。（如果本机装了 Xcode 但还没同意许可协议，
`xcrun` 会直接罢工；脚本会自己改走 CommandLineTools，不用你手动切。）

这个 `.app` 里装的是什么：

- **一台窗口 + 一个 WKWebView**。界面还是 `ui.html` 那一套，一行没改 —— 外壳不重画界面。
- **首启页**（`onboarding.html`）。第一次打开时，外壳先体检：解释器、Chromium、账号、
  转写组件，缺哪样就显示哪样待配置。点「我思故我在」开始补，补齐了自动进界面。
  转写模型不在这一步：它是进门之后在后台下的（视频页那盏灯显示进度）。以后每次打开
  直接进，不会再问一遍。
- **数据落在用户目录**，不在应用包里：`~/Library/Application Support/归藏/`
  （虚拟环境、导出的书、缓存、登录态都在那儿）。所以应用包本身只读、可以随便挪位置。
- **不打包 Chromium**。368MB 那个是全局缓存，首启页那一步会自己装。

排障：外壳本身不出声（双击启动的东西没有终端）。设了 `GUIZANG_DEBUG` 才会把关键节点
写到 `~/Library/Application Support/归藏/shell.log`：

```bash
open --env GUIZANG_DEBUG=1 dist/归藏.app
```

### macOS：打一个能发给别人的安装包

```bash
bash shell/make_dmg.sh          # 产出 ~/Desktop/归藏-<版本>.dmg（约 2MB）
bash shell/make_dmg.sh 安装包    # 仓库要的那份：直接打进 安装包/，只留最新一个
```

打好的那份就在仓库里：[`安装包/归藏-1.0.6.dmg`](安装包/归藏-1.0.6.dmg)，别人可以直接下载，
不用自己构建。（版本号只有一个来源，是 `ui_server.py` 里的 `VERSION`；界面「关于」那页、
.app 的 Info.plist、dmg 的文件名都从它取，所以这三处永远是一个数。界面里另有一个成对值
`ui.html` 的 `GUIZANG_PAGE`，写的是「这份界面是给哪版后端看的」，两处必须一起改，
静态门禁 `tests/check_route_pair.py` 会当场抓出漏改的那一处。）

`安装包/` 里这份跟着代码一起更新，只留最新一个，不留旧版本。装了 `.app` 的人重新装一次就能
拿到新功能；源码直接跑的人不受影响（界面从磁盘现读，后端换了进程即可）。

包里是 `归藏.app` + 一份《首次打开必读.txt》+ 指向 `/Applications` 的快捷方式。脚本会
把 dmg 挂起来自查一遍（应用在不在、执行位还在不在、源码进没进去、签名过不过），
不靠「打完了就当它没问题」。

**发给别人之前，把这四条如实告诉他**（都是这个包当前的真实边界）：

| 事项 | 现状 | 对方要做什么 |
|---|---|---|
| 苹果签名 | ad-hoc 自签，没有开发者证书，也没送公证（`spctl -a -vvv` 判 rejected） | 第一次打开按**右键 →「打开」**。若提示「已损坏，无法打开」就执行 `xattr -dr com.apple.quarantine /Applications/归藏.app`（装在别处的换路径，报 `Operation not permitted` 的加 `sudo`），或在 系统设置 → 隐私与安全性 里点「仍要打开」 |
| 本机 Python | 应用**不自带**解释器，靠机器上现成的 | 没有 Python 的话先去 python.org 装一个 3.9+；外壳会真跑一遍筛掉用不了的（比如没同意 Xcode 许可的 `/usr/bin/python3`），找不到会直说 |
| 首次下载 | 要下 Chromium 约 370MB | 网络要通。只开系统代理的用户也能装成 —— 外壳会把系统代理读出来交给下载步骤（playwright 的下载器只认环境变量，不读系统代理） |
| 平台 | 这份 dmg 只编了 macOS（通用二进制，arm64 + x86_64，最低 macOS 13） | Windows / Linux 要另外构建，见第九节 |

## 三、首次使用

1. 左上角齿轮 → 连接账号 → 在弹出的浏览器窗口里用微信扫码（会话持久保存在 `cache/browser_profile/`）。
2. 填「接口 Key」：微信读书网页版 → 设置 → 开放 API，复制形如 `wrk-…` 的 Key 粘进去保存。填一次即可，存在本机 `cache/config.json`（权限 600）。书架、笔记、统计、推荐、站内搜索、书籍详情都依赖它。
3. 想把划线导入 flomo，填「flomo」那一栏（flomo 网页版 → 设置 → API，形如 `https://flomoapp.com/iwh/xxxx/`），需要 flomo PRO。这一栏只管**往外推划线**；把自己在 flomo 记的东西收进来是「便签」那一格，走的是导入导出包，不需要这个 webhook。
4. 便签（flomo）：flomo 网页版 → 设置 → 导出数据，拿到那个 zip，在「便签」页右上角的三点菜单里选「导入 flomo 导出包」。导入按「时间 + 正文」认人，同一条点第二次不会重复入库。附件（图片）落在 `cache/flomo/att/`，账本在 `cache/flomo/notes.json`。第一次让 Agent 读你的便签之前，它需要先看到那份「记忆画像」（`cache/flomo/portrait/`，只由条数、标签、字数这些数字算出来，不含任何一条笔记原文）—— 界面上点一次「生成画像」即可，Agent 侧对应 `flomo_portrait`。
5. Z-Library：设置 → Z-Library，填邮箱与密码点登录（也可直接填网页端抄来的 userid / userkey）。登录只把令牌存进 `cache/zlib.json`（权限 600），**密码不落盘**。走的是安卓 App 那套接口，国内需要你的代理开着；域名默认 `1lib.sk`，进不去可在同一栏改。登录后「搜索」页右侧那栏就能搜书、下载，下回来的 EPUB / PDF 直接落进「本地书架」。
6. 外观：设置里「壁纸」选一张自己的图（存 `cache/wallpaper.bin`），页面铺满后会自动判断明暗来切换文字与玻璃颜色；「清除」恢复默认。
7. 「一键建立 MCP」把接入提示词复制到剪贴板，粘给你的 AI Agent 即可。提示词里不含任何本机路径、用户名、端口，可以直接给别人用。
8. AI 小结（章内总结 / 全文总结 / 一键导图）与划句问助手用的是**同一份**配置：设置 → 读书小助手，填一个兼容 OpenAI 的地址、Key 与模型名。没填时那两枚芯片会如实说「还没配 AI 接口」，不会假装总结过。
9. **更新过代码之后**（改了仓库里的 `ui_server.py`，或拉了新版本）：界面是从磁盘现读的，路由表却是进程起来那一刻装进内存的，所以旧进程会继续供着老接口。现在不用自己找那个窗口 —— 页顶会出一条横幅写明「本机后端是 x，界面是 y」，右边一颗「换新后端」，点一下后台换班、绑回同一个端口，页面自己刷新。后端正在跑任务时它不打断，等这一趟跑完再点。

## 四、功能地图

- **书架**：六格各自独立 —— **读书**（微信读书）、**本地书架**、**剪藏**、**订阅**、**视频**、**便签**，一篇文章只落在它自己那一格，别处搜不到、翻不到。每格自己有夹子、自己的标签、自己的排序；页右上角的三点菜单里能新建文件夹、改分类、打标签。瀑布流书卡（封面 + 状态标签），可拖拽归类；每批渲染 60 本，滚动续加载；状态标签（待读/在读/已读）不要求本地已抓取，书架上的书也能标。表头一颗「去搜索找书」直达搜索视图。**写作**是独立的一整屏、不住在这排芯片里，但稿子照样住在同一个书库。落在硬盘上也是分开的：`~/Documents/归藏/` 下按这些格各一个文件夹（含 `写作/`）。
- **封面**：剪藏拿文章首图，视频拿视频封面 —— 挑图时避开页头 logo 与头像，不会满书架一张脸。
- **后端成色自查**：进页面就跟本机后端对一次代码指纹，对不上就在页顶出横幅并写明两边版本，
  右边一颗「换新后端」一键换班（新进程绑回同一个端口，页面自己刷新）；在跑任务时不打断，
  真连不上才说连不上。界面上任何一次失败也按四种真相分别措辞，不再一句「服务没在跑」糊过去。
- **AI 小结**：一个入口、两种模式。读书一次只吃当前这一章，剪藏与视频转写笔记吃全文；「学习理解」走费曼那条路（讲清楚 → 找漏 → 给最小执行步骤），「归纳」只做简明扼要的压缩。两种模式各存一份，互不覆盖；同一屏可以一键出 SVG 思维导图，也能存成笔记。
- **便签（flomo）**：导入 flomo 的导出包，一条笔记收成一本形状相同的书，卡片头上写着时间（到分钟）、标签、字数与图数，按天分节；长条目自动折叠；标签按层级排成药丸，药丸写着几条，点进去就筛出几条。
- **写作**：AI 辅助写作，不代笔 —— 自己码字，卡住了选中/标注再让 AI 搭手。续写按用户挑的长度（一句 / 一段 / 提纲要点 / 一整节）流式接上；没灵感点「灵感」，每次给三个新角度、不重复推同一个；润色只给差异建议、逐块等你接受，不动原文。导出四种格式（图片 / PDF / 电子书 / Markdown），图片有多种排版模板可切换（黑白简约 / 商务蓝 / 青翠 / 米白书简），可加工具名与日期。稿子存盘带版本号，对不上会当面拒绝，绝不拿旧内容盖新内容。
- **个人主界面**：左上角头像点开，从左侧滑出——里头是你的简介区和两张热力图（今日学习时长、今日写作时长），原主页的功能也都在这一栏里切换（**点一下才切页**，以前指针划过就切，太容易误触，已改）。头像用「设置」里改，那颗「设置」入口挪到了个人主界面最下方。
- **书籍详情页**：点书卡进详情——简介、作者、出版社、分类、微信读书阅读进度与最近阅读时间、已读时长、划线/想法/书签数量、本地是否已抓取 Markdown；本地已有的书另给 完整包 / 正文 / 目录 / 补全图片。书城搜来的书另给「加入书架」，已经在架的显示「已加入书架」并置灰。
- **阅读计划**：给每本书定一个自己的节奏——每日或每周读几页，详情页上就能定、改、结束。页数按正文字数折算（每 1000 字一页），跟字号、窗口宽窄无关，所以「还剩多少页」是个每天都不会变的准数；进度只认往前读（翻回去查个词不会把「今天读了 30 页」缩水），今日 / 本周读了多少、照这个速度几号能读完、在不在轨上都算给你看。读完那一刻，当时定的目标与起止日期存进档案，之后再怎么改计划也冲不掉它。
- **搜索**：两栏并排——左边微信读书（取书：书城搜索、我的划线内容；划线结果点进去落到那本书的详情页），右边 Z-Library（直接搜书、下载，下回来的 EPUB / PDF 落进「本地书架」）。两边逻辑不同，所以各占一栏、各有各的结果与按钮；窗口窄到放不下时自动上下排。
- **批量**：批量抓取、批量加书架、批量导出（合并 ZIP）、批量改状态、批量加入待读、批量删本地缓存（删除前弹确认清单）。加书架不弹确认：勾选卡片本身就是意图。
- **知识卡片**：把某本书的划线导出成 `.apkg` Anki 卡包；也能在页面里直接卡片回顾（正面/背面、记得/不熟计数）。
- **随机漫步**：从全部划线里随机抽卡片，做无目的回顾。
- **划线笔记**：全书划线集中浏览，多选后一键导入 flomo（原文用「」包住，附书名与标签）。

## 五、接入 AI Agent（MCP）

配置里加一项，路径换成你自己的归藏目录：

```json
"guizang": {
  "type": "stdio",
  "command": "node",
  "args": ["<归藏目录>/mcp/guizang-mcp.mjs"],
  "timeout": 180000,
  "env": { "GUIZANG_REPO": "<归藏目录>" }
}
```

Qoder CN 写在设置文件的 `mcpServers`；ZCode 写在 `config.json` 的 `mcp.servers`。配好重启 Agent（MCP 是启动时加载的，不像 skills 能热加载）。

适配器找项目目录的顺序：环境变量 `GUIZANG_REPO` → 认「本文件就在项目 `mcp/` 下」→ 退回 `~/weread-exporter`。Python 解释器优先用项目自带的虚拟环境（Windows 认 `.venv\Scripts\python.exe`，macOS / Linux 认 `.venv/bin/python`），没有就退回系统 `python` / `python3`（可用 `GUIZANG_PYTHON` 指定）。

56 个工具，分十一类（逐个工具名的清单在 [`README.md`](../README.md) 的「接入 AI Agent」一节，那里是唯一一份，改动时跟着代码走）：

| 类别 | 数量 | 头两个 |
| --- | --- | --- |
| 书架与状态 | 6 | `shelf_list`、`app_status` |
| 取书与账号 | 4 | `book_fetch`、`batch_fetch` |
| 书与笔记 | 6 | `book_detail`、`notes_search` |
| 写回与导出 | 4 | `shelf_add`、`zip_export` |
| 网页剪藏 | 1 | `clip_url` |
| 订阅（RSS） | 8 | `feed_discover`、`feed_to_shelf` |
| 视频转笔记 | 8 | `video_capability`、`video_transcript_save` |
| 思维导图 | 3 | `map_show`、`map_save` |
| 画板 | 5 | `board_new`、`board_save` |
| 便签（flomo） | 2 | `flomo_notes`、`flomo_portrait` |
| 写作 | 9 | `writer_list`、`writer_read` |

数是 `mcp/guizang-mcp.mjs` 里现数出来的：`tests/check_mcp_tools.py` 每次门禁都会先 `tools/list` 再逐条走一遍，写死的数字对不上会当场报红。

取书是分钟到小时级的长任务，`book_fetch` / `batch_fetch` 会立即返回，进度用 `app_status` / `task_log` 轮询，不要在工具调用里等它跑完。`cache_delete` 要带 `confirm=true` 才真删。`shelf_add` 是唯一会动**真实微信读书书架**的写操作（官方网关只读，这一步走网页端接口，所以要用登录 profile 起一次浏览器，约 3-8 秒），其余写口只碰本机：`feed_*` 动订阅与本地图库，`board_*` / `map_save` 动那份 JSON，`flomo_notes` 只进不出。改转写用 `video_transcript_save` 的 `edits` / `drop` / `add` 说「改了哪几段」，适配器自己读回整本再写盘 —— 后端那三个写口全是整本覆盖，把整本抄一遍发上去就是这一层要挡住的事故。

网页端 `/mp/` 接口认的是两套 cookie：`wr_vid`（长期，代表是谁）与 `wr_skey`（约 30 天，代表会话还在不在）。只查 `wr_vid` 会把「skey 到期」误判成已登录——接口回的是 `{"errcode":-2012,"errmsg":"登录超时"}`，看着像书的问题。`shelf_add.py` 因此先看 `wr_skey`，缺就先访问一次首页续期（访问任意微信读书页面，服务端会重新下发 skey），发请求后仍收到 -2012 再续一次重发；两趟都不行才让你去扫码。错误文案照抄服务端 `errmsg`，不猜码值含义。

## 六、命令行用法（不经界面）

macOS / Linux（解释器是 `.venv/bin/python`）：

```bat
.venv\Scripts\python.exe export_precise.py <ID> --headed
set EXPORT_DEBUG=1 && .venv\Scripts\python.exe export_precise.py <ID>
```

## 七、产物位置

书库根目录：源码直接跑是项目下的 `output/`，装成 app 是 `~/Documents/归藏/`（设置里可换）。
根下面**一格一个文件夹**，名字就是书库里的那些格：`微信读书/`、`本地书架/`、`剪藏/`、`订阅/`、`视频/`、`便签/`、`写作/`。

```
<书库>/<模块>/<书号>/meta.json        书名/作者/是否导完（界面据此显示百分比与「导出成功」）
<书库>/<模块>/<书号>/chapters/NNNN.md 逐章正文
<书库>/<模块>/<书号>/images/          插图
<书库>/<模块>/<书号>/raw/NNNN.json    每章图片 URL 与字数
<书库>/<模块>/<书号>/_catalog.json    这本书的目录快照（取书与剪藏这类带目录的才有，视频那一格没有）
```

视频那一格另有 `transcript.txt` / `transcript.json`（转写）与 `summary.json`、`merged.md`。
合并稿 `<书名>.md`（图片是相对路径，单拿它会断图；界面的「完整包」ZIP 已把图片平铺好）落在
它自己那一格的根下（`<书库>/微信读书/<书名>.md`）；Anki 卡包 `<书名>.apkg` 生成在
`cache/apkg/`，导出完界面上直接给路径。

便签的账本不在书库而在数据目录：`cache/flomo/notes.json`（条目）、`cache/flomo/att/`（附件图）、
`cache/flomo/portrait/`（记忆画像）。书架本身的账本（夹子 / 排序 / 状态 / 标签）在
`cache/library.json`，**按模块分格** —— 剪藏那一格的夹子不会出现在读书那一格的下拉里。
两张热力图的时间账在 `cache/activity.json`，头像在 `cache/avatar.bin`，都只在本机。
阅读计划那本账在 `cache/readplan.json`（每本书的节奏、每日 / 每周读了多少、读完的档案），
Z-Library 的登录令牌在 `cache/zlib.json`（权限 600，只存令牌不存密码）。
写作那一格的形状不同：`<书库>/写作/write_<书号>/` 下是 `draft.md`（正文唯一真源）、
`meta.json`（标题 / 字数 / 版本号 / 时间 / 已看过的灵感角度）与 `versions/`（快照，回退用）。

## 八、安全说明

- 服务只绑 `127.0.0.1`，不对外监听；POST 接口要求 `Content-Type: application/json`。
- 接口 Key 与 flomo 地址存在本机 `cache/config.json`，文件权限 600；界面上只回显 Key 的末 4 位。
- 所有按 id 取目录的接口都过正则 + `realpath` 双重校验，防止路径穿越；图片写盘前校验魔数。
- Z-Library 的登录只落令牌（`cache/zlib.json`，权限 600），**密码只在登录那一次用、不落盘**；界面上也只回显令牌末 4 位。
- 源码里不含任何个人路径、用户名、端口或密钥，可直接分发。
- `cache/`、`output/`、`.venv/` 已在 `.gitignore` 里，提交不会带上你的账号会话与书籍内容。
- 便签（flomo）导入的那份账本与附件全在 `cache/flomo/` 下，只在本机；给 Agent 看的那份「记忆画像」是由条数、标签、字数算出来的骨架，**不含任何一条笔记原文** —— 要原话得由 Agent 明确用 `flomo_notes` 一条一条取。
- 测试夹具里的便签内容是现编的（`tests/flomo_fixture.py`），仓库、文档与截图里不会出现你真实的笔记文字；`tests/check_privacy.py` 每次门禁都扫一遍。

## 九、跨平台差异

最初只在 macOS 上跑，几处「平台唯一解」写死在业务代码里。Windows 上的症状不是报错，而是**点了按钮毫无反应**：后端拿 `.venv/bin/python` 去起子进程 → 找不到文件 → 异常逃出请求处理函数 → 连接被掐断 → 前端 `await` 直接 reject → 页面不吭声。现在这些差异全部收在 `platform_compat.py`：

| 事项 | macOS / Linux | Windows |
| --- | --- | --- |
| 虚拟环境解释器 | `.venv/bin/python` | `.venv\Scripts\python.exe` |
| Playwright 浏览器缓存 | `~/Library/Caches/ms-playwright`（Linux 是 `~/.cache/ms-playwright`） | `%LOCALAPPDATA%\ms-playwright` |
| 让子进程自成一组 | `start_new_session=True` | `CREATE_NEW_PROCESS_GROUP`（`start_new_session` 在 Windows 上会被静默忽略） |
| 中止任务（先好好说） | `SIGTERM`，引擎收到后把在手章节落盘再退 | 同控制台的 `CTRL_BREAK_EVENT`，引擎里注册 `SIGBREAK`；发不出去才退化为硬杀 |
| 强制结束（连子孙） | `os.killpg(SIGKILL)` | `taskkill /PID x /T /F`（浏览器是 python 的子进程，只杀 python 会留下它占着 profile 锁） |
| 清残留浏览器 | `pkill -f <profile 绝对路径>` | PowerShell `Get-CimInstance Win32_Process` 按命令行字面匹配后 `Stop-Process -Force` |
| 打开文件管理器 | `open` / `xdg-open` | `os.startfile` |

两处环境变量：`GUIZANG_PYTHON` 指定解释器；`GUIZANG_HIDE_WINDOW=1` 让任务子进程不占控制台窗口（代价是 `CTRL_BREAK` 发不出去，「中止」退化为硬杀——引擎每攒够一段就自动落盘，损失有上界）。

服务起来时会打印一行「解释器 / 浏览器」的实际取值，排障先看这两行。

另外，所有前端发起的操作在后端都包了一层兜底：真出错时不会再掐断连接装死，而是把异常类名、消息和最后几行栈写进「进展」栏，页面上也能看到红字。

## 十、关于两种 id（容易踩）

阅读器链接里的 id（如 `1a2b3c4d5e…`）与书架的 `bookId`（形如 `33xxxxxx` 的纯数字）**是两套命名空间**。本地导出目录用前者；调官方 `/book/info`、`/book/getprogress` 取简介与进度要用后者；笔记索引存的是后者。对应关系藏在书架项 `deepLink` 的 `?v=` 参数里，前后端都做了双向映射（后端缓存 10 分钟）。另外官方网关的参数名不统一：`/book/bookmarklist` 用 `bookId`，`/review/list/mine` 用小写 `bookid`。

## 十一、已知限制

1. 正文靠 hook Canvas 的 `fillText` 取字，阅读器会复用已绘制的缓存，所以整本抓取本质上不保证 100%；引擎已按目录标题分章，并有硬超时与断点续传。
2. 章节归属在两次导出之间可能略有差异（阅读器绘制批次不同），但正文总量稳定。
3. 官方网关不开放「书单」接口，面板里因此没有书单，最接近的是「推荐」。
4. flomo 的请求格式官方未公开示例，这里按通行约定发 JSON、失败自动退回表单编码。
5. 部分出版社限制网页端阅读（显示「去 App 阅读」），此类书无法导出。
6. 仅可用于导出自己已购内容，请勿分发成果。
7. **macOS 应用没送公证**（ad-hoc 自签），别人拿到要从右键 →「打开」进来，原因与做法见第二节。要做成双击无提示，只能买苹果开发者账号走签名 + 公证，这一步没有便宜的替代。
8. **应用不含 Python 解释器**，靠机器上现成的（3.9+）。外壳会逐个真跑一遍筛掉用不了的，但机器上确实没有 Python 时，得由用户自己装一个。
9. 首次运行要下载约 370MB 的 Chromium，网络不通就装不完。应用会在检测到系统代理后把它交给下载步骤，但代理本身得用户开着。
10. 目前只有 macOS 的成品 dmg。Windows / Linux 的启动脚本在仓库里，`.app` 本身不通用。
11. 便签这一格是**只进不出**的：导入认 flomo 自己导出的那份 zip，工具不回写 flomo。导入按「时间 + 正文」认人，所以在 flomo 那边改过正文再重新导入，会被当成新的一条。
12. AI 小结与一键导图依赖你自己填的兼容 OpenAI 接口（设置 → 读书小助手）。没填时界面会如实说「还没配」，不会给一份看起来像总结的空白；填了之后，送出去的那段文本走的是你填的那个地址，与微信读书无关。
13. **Z-Library** 走的是安卓 App 那套接口（eAPI），没有官方文档、形状随对方变动；国内需要你的代理开着才能连上，可用域名也会变（默认 `1lib.sk`，进不去就在设置里换）。只收 EPUB / PDF，下载额度受账号限制；登不上或下不动时会如实报原因，不会假装成功。
14. **阅读计划的一页是折算出来的**（1000 个正文字符记作一页），跟屏幕上的一屏不是一回事 —— 阅读器是连着滚的，没有一个物理「页」。这么定是为了让「还剩多少页」跟字号、窗口宽窄无关，同一本书今天明天是同一个数。
