# 归藏 · 交接说明（1.0.1 · 第三十一轮 · 2026-10-04）

这份文件给「接手这一轮改动的人」看：这一轮改了什么、根因是什么、哪些地方还差验证。
装与跑看 `部署说明.md`，改代码的规矩看 `开发规范.md`，谁调谁、模块边界看
`架构与模块地图.md`（§2 模块表 / §3 六条主链路 / §7 前端那几个反复踩到的事实）。

一句话交接：**这一轮把「六条来路」真的分成六格**——界面上、账本里、磁盘上三处同时分家，
以前那种「剪藏的文章混在书架里、几百本平铺在书库根下」的糊状结构没有了；散在各处的 AI
出口收成**一个「小结」入口、两种模式、三种内容**（读书只喂当前章，剪藏 / 视频整篇），
一键出 SVG 导图；新接一条便签（flomo）：走官方导出而不是碰账号凭证，导进来当普通条目，
并给用户自己生成一份**不含原文**的记忆画像，让 Agent 先读它再动手。封面这件事补上
（剪藏取文章首图、视频取视频封面，内网地址一律不进本机）。另有一处会**吃掉笔记的真竞态**
被从根因修掉（§1 最后一段）。版本号 `1.0.0 → 1.0.1`，`.app` 与 `dmg` 重打（见 §6）。

---

## 1. 这一轮改了什么

### 三个新模块

| 模块 | 它管的事 | 为什么单独一个文件 |
|---|---|---|
| `book_layout.py` | 书库的目录结构：一本书该住在哪个文件夹、书号前缀反查是哪个模块、老位置的归置（migrate） | 「哪六个模块、各叫什么、各落在哪一层」这件事被后端账本、磁盘目录、界面左栏三处消费。写在一处才不会出现「界面上分开了、磁盘上还平铺着」这种半吊子；`MODULES` 是唯一出处 |
| `ai_sum.py` | AI 小结：一次读多少（范围）、怎么问（模式）、结果存哪儿 | 它不碰网络、不读界面配置：正文由调用方喂进来、LLM 由调用方去问、落盘由调用方给目录。于是「没起服务、没配 Key」也能被完整测一遍（`tests/check_ai_sum.py`）。两条硬口径（读书只处理当前章 / 学习理解 vs 归纳）写在文件头，不散在前端 |
| `flomo_notes.py` | flomo 官方导出的那份 HTML zip：解析、抽标签、附件落盘、按「时间 + 正文」认人做增量、导成一格条目、算记忆画像 | 认的是别人家的文件格式，改版就只改这一处；画像与条目的口径（字数、标签层级、id 怎么算）必须与后端接口、MCP 那两处一致，分开放迟早对不上 |

### 六格分家：一处定义，三处跟着分

- **磁盘**：`<书库>/<模块中文名>/<书号>/`，比如 `~/Documents/归藏/剪藏/clip_xxx/`。
  **书号本身没变**（`clip_ / feed_ / video_ / imp_ / flomo_` 这些前缀照旧），变的只是它
  挂在哪一层；老书库靠 `book_layout.migrate` 搬，**只搬不覆盖**，目标位已经有东西就报错不动手。
- **账本**：`cache/library.json` 从平的那一份变成 `{"modules": {weread: {folders, assign,
  order, state, tags}, clip: {…}, …}}` —— 一格一份分类账，文件夹与标签**不跨格通用**。
  旧的平铺账本在首次读的时候迁进各格（`ui_server.py` 的 `lib_load` / `lib_scope`）。
- **界面**：左栏六格按 `book_layout.ORDER` 排；剪藏的文章只在剪藏格里出现，
  书架那一屏不再混展示。每格右上角 ⋯ 菜单里给「新建文件夹 / 分类 / 打标签」，
  作用域就是这一格。

### 封面这件事补上

- 剪藏：`clip_article.first_image` 挑文章首图 → `pick_cover` 定夺 → `cache_cover` 落到
  `cache/covers/`；`safe_image_url` 那道门把**本机、内网、非 http** 一律挡掉（SSRF 不给过）。
  `web_parse._zhihu` 这一轮也改走 `pick_cover`，知乎的 og:image 不再直接写进 meta。
- 视频：用 yt-dlp 回来的 `info["thumbnail"]` 当笔记封面（这条本来就在，这一轮由
  `tests/check_covers.py` 把它钉住，防止以后有人改成首帧截图）。
- 两边都没有图：书卡与详情页退到书名首字，不留一块空洞。

### AI 小结：一个入口、两种模式、三种内容

- 路由：`GET /api/ai/summary`（读回存过的那份）+ `POST`（流式，SSE）+ `/api/ai/mindmap?mode=svg`。
- 范围口径是用户定的：**读书一次只处理当前这一章**（整本喂进去既烧钱又答得空），
  剪藏 / 视频 / 订阅这类「本来就是一篇」的内容整篇读。
- 模式两档：**学习理解**（费曼那一路：讲透 + 最小执行步骤 + 逼用户输出一次）与**归纳**
  （挤水分，只留能扫完的要点）。
- 模型配置共用「设置 → 读书小助手」那一份（`agent_cfg()`）。没填就直接说
  「还没配 AI 接口：设置 → 读书小助手，填地址和模型名」，**不假装总结过**。
- 结果落 `<书目录>/summary.json`；半路断线与「答完了」分开处理（见 §5）。

### 便签（flomo）这一格

- **走导出文件，不接 API**：flomo 读笔记只有两条路——网页版设置里导一份 HTML zip，
  或者官方 MCP（要 MAX 会员 + 个人 Token）。导出的那份谁都能拿到，程序也不碰账号凭证；
  界面留一颗「重新导一次」，想更新点一下，比挂一条要会员的长连接实在。
- 落盘：`cache/flomo/{notes.json, att/, portrait/}`。条目 id = `fm_ + sha1("时间|正文")[:12]`
  —— **所以正文原样存**，标签 `#一级/二级` 就地留在正文里（flomo 本来就这么写），
  只在交付那一刻清洗（`public`）。存储里动一刀，重复导入就出现「同一条两个 id」。
- 界面：一天一根分隔线，卡头上写着时间、标签与字数；下面那排药丸「写几条就筛出几条」；
  长笔记自动折叠。**只进不出**——不写回 flomo。
- 记忆画像（`portrait/`）：标签分布、记录节奏、字数、Top 标签这类统计口径，
  **不含任何一条笔记原文**。MCP 里 `flomo_portrait` 让 Agent 先读画像（读它比读一百条便宜），
  要原文再 `flomo_notes`。

### MCP 45 → 47（十类）

新增 `flomo_notes`、`flomo_portrait`（便签那两个只读，取的是后端摘过标签的 `plain`，
Agent 读到的和屏幕上是一条样）。类别与个数以 `tests/check_mcp_tools.py` 现读 `tools/list`
为准 —— 文档里那些数字不许凭记忆写。

### 修掉一处会吃掉笔记的竞态（这一轮的硬伤）

症状：删一条划线 → 点右下角「撤销」→ 线回来了，过一会儿又凭空消失；运气差时后一笔存盘
把「没有」写进书文件夹，笔记真丢。

根因在 `ntSave()`：存盘是 900ms 防抖 + 一次 POST，回执里带着服务端整理好的那份 doc
（id、时间戳、排序都是它补的），代码无条件 `NT.doc = d.doc`。**那份回执是「出发那一刻」的
快照**——请求还在路上的时候用户又落了一笔（撤销、接着再划一句），这一笔就被旧快照盖掉了。
整轮门禁里 `tests/check_notes_editor.py` 偶发的那一次红，撞的就是这条时序。

修法：每次 `ntTouch()` 记一个版本号 `NT.rev`；回执只在 `NT.rev` 没动的时候才认，
动过就以本地为准并再存一次；上一笔没回时新的一笔排队不插队（两条 POST 乱序落地时，
不能让先出发的那份后写进磁盘）。这条竞态现在有一套**固定摆出来**的断言：把那一笔的回执
人为压住 1.5 秒，在回执落地之前点撤销，然后要求本地、笔记栏、正文墨迹、服务端四处都是
那道线（`撤销不会被半路的存盘回执抹掉（回执按版本号认）`）。

## 2. 这一轮**没有**碰的东西

- 取书引擎（`export_precise.py`）、图片下载、EPUB / PDF 导出、云同步、转写流水线没改。
- 阅读器正文的重排与分章逻辑没动（动的只有右栏那一套与六格分家带来的路由参数）。
- 没有新增依赖：`book_layout.py` / `ai_sum.py` / `flomo_notes.py` 都只用标准库。
- flomo 只进不出，也不接官方 MCP 那条要会员的长连接。

## 3. 还没验过的（诚实清单）

- **flomo 那条线只喂过一份真实导出的「形状」+ 一套现编夹具。** 解析器是照本机一份 555 条
  的导出写的，但**没在别人的导出包上跑过**（不同年份、带公众号卡片、带待办的形状会变）；
  时间线在几千条、几百张图下的性能**没测过**。「重新导一次」的增量只在夹具上连跑两轮。
- **「Agent 先读画像再动手」这条流程没有端到端跑过。** 验的是两个工具各自能返回什么，
  不是拿一个真 Agent 跑一遍「首启 → 读 `flomo_portrait` → 带着画像操作」。
- **AI 小结的输出质量没有评测。** 范围切分、提示词长什么样、模型回的烂 JSON 怎么兜，
  都有断言；「答得好不好」这件事自动测不了，也没人工评过。
- **老书库归置（`book_layout.migrate`）没在真实老书库上跑过** —— 沙盒里都是现铺的夹具。
  真机上第一次升级到 1.0.1 时，那一次搬动值得先备份再点。
- **两个包没有在别人的机器上装过。** `.app` 与 `dmg` 只在本机自检通过；未签名未公证，
  首次打开要右键「打开」或 `xattr -dr com.apple.quarantine`。
- **Windows / Linux 未端到端验证**（老问题：跨平台分支只在单测里 mock 平台标志跑过）。
- 语音转写的**准确率**没有系统评测过（只有单条流水线的端到端）。
- 「清除本地数据」删登录态之后要重新扫码；这条提示写在界面上，但**没在真机上走完
  「删掉 → 重开 → 重新扫码」**。

## 5. 已知的坑（都踩过，写下来省下一次）

| 症状 | 根因 | 解法 |
|---|---|---|
| 撤销点下去，那道线过一会儿又消失 | 存盘回执是「出发那一刻」的快照，`ntSave` 无条件拿它覆盖本地 doc，把路上刚落笔的那一笔抹掉 | 每次 `ntTouch` 记 `NT.rev`；回执只在 `rev` 没动时才认，动过就以本地为准再存一次；上一笔没回时新的一笔排队 |
| 整轮门禁一片红（尤其 MCP 那两套），单独跑又全绿 | `tests/seed.py` 与服务用的 `GUIZANG_*` 不是同一套：书架铺在 `/tmp/guizang-selftest`，服务读的是另一个目录 | 四个变量（`GUIZANG_SELFTEST_DIR / GUIZANG_DATA / GUIZANG_BOOKS / GUIZANG_SHOT_DIR`）一起导出，铺书架和起服务用同一套；漏了 `GUIZANG_BOOKS` 的套件会去旧位置找书，报「notes.md 没落盘」这种假失败 |
| 套件里想「压住一个回执」来摆竞态，结果时序全乱 | sync Playwright 下 Python 一 `time.sleep`，事件就不下发了，`page.route` 的 handler 根本不跑；而延迟如果连请求一起推迟，出去的那一份已经带着改动之后的内容，什么也测不出 | 延迟放进页面里的 JS 定时器（包一层 `window.fetch`），**只推迟回执、请求照原样先出发** |
| `page.evaluate` 里的 JS 正则在导入时报 `SyntaxWarning: invalid escape sequence` | Python 普通三引号会把 `\d`、`\/` 当自己的转义处理 | JS 段一律写 `r"""…"""` |
| flomo 重复导入出现「同一条两个 id」 | id 是 `sha1("时间\|正文")`，正文动一个字就成了另一条 | 存储里正文原样不动，标签与格式只在**交付时**清洗（`flomo_notes.public`） |
| AI 小结半路断线之后，上一次的成品被一个空文件顶掉 | 「流没跑完」被当成「答完了」，照样落盘 | 落盘只在拿到完整内容之后；半路失败保留上一份旧结果，界面如实说这次没成（`ui_server.py` 的两处判据） |
| 剪藏 / 订阅的文章还出现在书架那一格 | 分类账还是平的那一份，谁都能查到谁 | 一格一份账（`library.json` 的 `modules{…}`），旧账本迁入各格；界面取数一律带模块名 |
| 栏名「看哪些」「范围」竖成一列 | flex 行里放**裸文本节点**，后面还跟着几颗钮 → 文本被压到只剩十几像素 | 标题包一层 `span` 配 `nowrap` + `flex:none`，行加 `flex-wrap` |
| 小条里七颗标签钮各一个字一行 | `.selpop .selnote .row` 继承了设置面板那条 `.row{padding:10px 12px}`，白吃 24px | 显式 `padding:0`；标签行 `flex:1 0 100%` 且允许折行；钮 `nowrap` + `flex:none` |
| 判「文字占了几行」判错 | `Range.getClientRects()` 会把 `text-overflow:ellipsis` 那个「…」也算一个 rect | 用高度 ÷ 行高来数行；探针要先自证抓得到真竖排 |
| 服务端口挪窝之后 MCP 找不着 | 服务会从默认端口往后找空位，而适配器只拿到「请它用的」那个数 | 服务绑到哪个口就把口写进 `runtime.json`，适配器认这个回执 |
| dmg 打完了在仓库里找不到 | `make_dmg.sh` 不传参数默认丢桌面 | `bash shell/make_dmg.sh 安装包`（`开发规范.md` §8 就是这么写的） |
| 新增 `const st` 直接语法错 | 同一个函数作用域里 `st` 已被「语音识别」那一行占用 | 换名（`mst`）；inline JS 门禁会当场抓出来 |
| 文档里的门禁项数过期 | 加减套件时忘了同步 | 项数写在 `开发规范.md` §7 与本文 §4；改套件就一起改 |

## 6. 版本与产物位置

- 版本号单一出处：`ui_server.py:57` 的 `VERSION`（**1.0.1**）。`shell/build_macos.sh` 与
  `shell/make_dmg.sh` 都从这个值读，不另写一份。
- 成品：`dist/归藏.app`（3.6 MB，x86_64 + arm64，ad-hoc 签名）与
  `安装包/归藏-1.0.1.dmg`（1,998,766 字节 ≈ 1.9 MB）。这一轮重打了两个包，并把过期的
  `归藏-1.0.0.dmg` 从 `安装包/` 里删掉（历史在 git 里）。
  **修完 §1 那个竞态后又重打了一次** —— 早先那份包里是修复前的 `ui.html`（差 998 字节），
  所以打包顺序是「改动落地 → 门禁 → build → make_dmg」，别反过来。
- 包内源码与工作树**逐字节比对通过**：36 个文件 sha256 全一致，包里没有多出工作树里没有的文件。
- 隐私扫描（`tests/check_privacy.py`）扫 82 个会被推送的文件：干净，没有个人信息、
  凭证或本机路径。
- README 里的截图在 `docs/shots/`（**六张**：书架 / 阅读器 / 脑图 / 订阅 / 视频 / 便签，
  这一轮新增 `flomo.png`）——图里全是沙盒夹具的假数据，不含任何真实书名、账号或本机路径。
