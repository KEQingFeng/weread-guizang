# 归藏 · 交接说明（1.0.3 · 第三十二轮 · 2026-10-04）

这份文件给「接手这一轮改动的人」看：这一轮改了什么、根因是什么、哪些地方还差验证。
装与跑看 `部署说明.md`，改代码的规矩看 `开发规范.md`，谁调谁、模块边界看
`架构与模块地图.md`（§2 模块表 / §3 六条主链路 / §7 前端那几个反复踩到的事实）。

一句话交接：**这一轮是修复轮，而三条被点名的 bug 是同一条根因**。用户报「画板笔记后端
起不来、思维导图后端起不来、导入 flomo 包没反应」，后端**一条实现都不缺**——缺的是「端口上
那个进程是不是手上这份代码」。界面每次请求都从磁盘现读（永远是新的），路由表却是进程起来
那刻装进内存的（可能是几周前那版），于是新功能一律 HTTP 404，而页面那句笼统的 `catch`
把它报成「本机服务没在跑」，把人带去查一件本来没事的事。现在的做法是：**四个入口 + 界面
都认同一份代码指纹**（`sha1(ui_server.py 字节)[:12]`），对不上就在页顶出一条横幅，两边
版本号各写各的，右边一颗「换新后端」走 `POST /api/restart`，接班人绑回同一个端口，
页面自己刷新；**换不成时说的是后端给的那句原因**，不是猜的。顺带修掉一处「存好了还标着
待存」的时序（§1 最后一段）。版本号 `1.0.1 → 1.0.3`，**本轮不构建安装包**（见 §6）。

## 1. 这一轮改了什么

### 认人，而不是认「在不在」：`platform_compat.py` 添的六把尺子

以前每一处启动逻辑都问「8770 有没有人应答」。**旧后端照样答**，于是被当成「服务在跑」，
新代码只好把服务往后面的端口挪——而浏览器和 MCP 适配器只认 8770，用户看到的就是 404。
现在问的是「应答那个是谁」：

| 函数 | 它回答的问题 | 为什么得单拎出来 |
|---|---|---|
| `code_fingerprint(path)` | 磁盘上这份 `ui_server.py` 是哪份代码（sha1 前 12 位） | 版本号比不出来：源码直接跑的人改完代码不动版本号，旧进程和新代码写着同一个 1.0.1，谁也不认谁是旧的 |
| `port_is_heard(port)` | 有没有人听（原名 `_free_port`，返回值和名字正好相反） | 接管端口这种护栏里，一个反着的名字就够把「有人占着」读成「空的，直接起」 |
| `backend_identity(port)` | 端口上那个进程自报 `{version, code, running}` | 走无代理 opener：本机回环不该被 Clash 那类全局代理绕出去，绕出去就连不上，然后被误判成「服务没在跑」 |
| `port_listener_pid` + `is_our_backend` | 那是谁的进程、命令行里有没有 `ui_server.py` | **这是接管唯一的护栏**：查不到就当不是自己的，绝不动手 |
| `stop_backend(pid)` | 请它退出：先 SIGTERM 让它自己收尾，等不到再硬杀 | 硬杀会把正在写的书文件夹留在半路 |
| `port_verdict(port, script)` | 启动器该干什么，回五种动作之一 | 见下表；四个入口都问它，不再各写各的判断 |

`port_verdict` 的五种动作，每个入口照它行事：

| 动作 | 含义 | 入口怎么做 |
|---|---|---|
| `free` | 没人听 | 正常起 |
| `reuse` | 正是手上这份代码 | 直接开界面，不再起第二个 |
| `takeover` | 是自家旧后端且没在跑任务 | 带 `--takeover` 起：停掉旧的、自己接管同一个端口 |
| `busy` | 是自家旧后端，但任务正在跑 | 不起第二个、不打断它，照样开界面（页顶横幅提示跑完再换） |
| `stranger` | 不是归藏，或问不出话 | 绝不动它，说明谁占着、怎么换端口 |

`python platform_compat.py verdict 8770` 把这套判断做成一行可执行输出（`动作|说明`），
Swift 壳不方便调 Python 库，就 `Process` 调这一句（八秒不返回就退回「unknown」按老路子开界面）。

### 后端：`/api/restart` + `--takeover` / `--handoff`

- `CODE_HASH`（`ui_server.py:63`）跟着 `/api/state` 一起报出来，`runtime.json` 也写一份，
  于是界面、启动器、适配器三处能对齐同一个值。
- `--takeover`：起来前先看端口上是谁，是自家旧后端才接管。
- `--handoff <pid>`：`/api/restart` 专用——等那个 pid 退出再绑**同一个端口**。另找端口等于
  把用户当前那个页面丢掉，所以宁可等。
- `restart_backend()` 先 spawn 接班人（`--handoff` + `--takeover`），回执送出去之后延迟一拍
  再 `os._exit(0)`；起不来就把原因回给人看，不把人晾在原地。
- 只接本机点过来的请求（这服务本来就只听 127.0.0.1），不做鉴权。

### 界面：`GZ` 状态 + 横幅 + `gzApi`（`ui.html:4243-4358`）

- `GUIZANG_PAGE = "1.0.3"` 与后端 `VERSION` 成对（`tests/check_route_pair.py` 钉着这条）。
- 每次 `/api/state` 轮询（2.6 秒一次）把后端的 `version` / `code` 记进 `GZ`，版本对不上
  就置 `GZ.stale` 并挂横幅。
- **报错那句不能编**：`gzApi` 把失败分成四类，各有各的说法——`down`（连不上）、
  `stale`（后端认不得这条接口，多半比界面旧）、`http`（回了 5xx/4xx，附上后端原话前 60 字）、
  `bad`（回了话但读不懂）。原来的 `catch(() => null)` 把四种揉成一种，所以只能说一句假话。
- 「换新后端」的三种没换成，话是三句：后端给了原因就用它那句（「在跑任务不打断」「新后端
  起不来」只有它自己知道）；答不上话给手动路径；连不上就说连不上。
- `GZ.why` 粘在横幅上，直到用户点「先不管」或版本对上了才让位——否则刚看到的答案会被
  下一次轮询盖回去。
- 换班成功后 `gzWaitBack()` 认「代码指纹变了」来 `location.reload()`，用户不用自己动手；
  30 秒没等来就明说去看 `/tmp/guizang_server.log` 最后几行。

### MCP 适配器：`alive()` 换成 `identity()`

`mcp/guizang-mcp.mjs` 里那段「端口有人答就算服务在跑」改成自报身份比对；磁盘指纹用 Node
自己算（`createHash("sha1")` 前 12 位，**算法与 Python 那份必须完全一致**，门禁逐项对）。
判定比界面旧时抛的是 `staleNote(who)`——一句带两边版本号、带「在跑任务就别打断」的人话，
而不是把 404 透传给 Agent。拉服务时补上 `--takeover`。

### 两个启动脚本与 macOS 壳：不再互相当「对方的服务起了」

`启动归藏.command` / `.bat` / `shell/main.swift` 改成同一个形状：先问 `port_verdict`，
按动作分派。以前最糟的是「脚本以为壳起了、壳以为脚本起了」两边干等；现在四个入口认同一把尺子，
`.bat` 这一轮还补了 `GUIZANG_PORT` 可覆盖（8770 被别的应用占着时用得上，MCP 适配器读同一个变量）。

### 四处新增门禁（现在静态 20 + 真机 20，共 40 项）

| 套件 | 它守什么 | 为什么单开 |
|---|---|---|
| `tests/check_route_pair.py`（静态） | 版本号成对、界面与适配器里每个 `/api/...` 都落在后端路由表里、「本机服务没在跑」这类谎话只许出现在注释里 | 不联网不开浏览器就能把这一类事故挡在门外；新功能「只写了前端没写后端」当场红 |
| `tests/test_backend_identity.py`（真机） | 指纹三处算法一致、旧后端能被接管、在跑任务时不许打断、不是归藏的进程绝不碰、一键换班真能换 | 这套判断最容易出两种假绿：静态看着对、端口上不一定 |
| `tests/check_swapbar.py`（真机 Playwright） | 横幅本身：认得出旧后端、说清谁旧、一键换得掉、换不掉时给明白话、点了「先不管」就别再烦人 | 只拦改写后端「答的话」（`/api/state` 的 version/code、`/api/restart` 的四种回执），真换班归上面那一套。横幅是这条根因唯一对用户露面的地方 |
| `tests/smoke_api.py`（自起服务，63 条） | 接口层那张网：GET 路由逐个有回声、三条被点名的功能走到底、安全动作能改能撤、坏输入不许把连接断掉 | 这类毛病单看一个接口看不出来，得「每一条都打一次」。自己起服务、自己铺书架、跑完整个包删掉——它要写画板/导图/标签/文件夹/便签账本，跟门禁那份共享沙盒混在一起会让别的套件看到不该看到的格子 |

### 修掉一处「存好了还标着待存」的时序（`ui.html` 的 `vtSave`）

症状：转写工作台点保存，回执都写了「存好了 8 段」，工具条那颗按钮还红着标「待存 3 处」。
根因：`vtSave()` 清掉改动集（`VT.edits/gone/extra/trash`）之后，工具条要等后面
`await vtRefresh()` 才重画——快机器上下一帧就盖过去了，机器忙的时候能多挂半秒，
而用户看到的正是那半秒。修法：清完立刻 `vtTools()`，让「回执」和「清零」同一帧落地。
这套件的 FAIL 是整轮门禁里偶发出现的（单独跑必绿），因为它撞的是负载下的时序。

  `/api/board`、`/api/mindmap`、`/api/flomo*` 的实现本来就是完整的（1.0.1 那轮就在了）。

- 取书引擎、图片下载、EPUB / PDF 导出、云同步、转写流水线、阅读器正文没动。
- 没有新增依赖，也没碰 `requirements.txt` / `bootstrap.py`。
- **本轮不构建安装包**：`dist/归藏.app` 与 `安装包/归藏-1.0.1.dmg` 是上一轮的产物，
  内容不变（见 §6）。

## 3. 还没验过的（诚实清单）

- **真换班只对着「现编的旧后端」验过。** `test_backend_identity.py` 在系统临时目录里放一个
  脚本名叫 `ui_server.py` 的假后端冒充 0.9.8（`platform_compat` 认的就是命令行里这个名字），
  端口、回执、交接都是真的，但**没在真装过 `.app` 的机器上跑过一次「装的那版被源码版接管」**。
  壳里的进程由 LaunchServices 拉起，命令行可能与沙盒夹具不同，那条路没走过。
- **Windows 分支没端到端跑过**：`netstat -ano` / `Get-CimInstance` 这两段是照文档写的，
  本机只有 macOS；`.bat` 新增的 `GUIZANG_PORT` 也只做过读代码层面的检查。
- **Swift 壳的 `verdict` 退化路径没在真机触发过**（八秒不返回当 unknown）。逻辑简单，
  但「简单」不是「验过」。
- **横幅与换班只在 Chromium 验过**；Safari 上 `AbortController` + `fetch` 那套没实测。
- **冒烟套件证明的是「有回声」，不是「答得好」**：它断言形状、条数、能不能撤销，
  不校验画板内容、导图坐标或便签清洗的质量（那些各有专门套件）。
- 装过 `.app` 的用户这一轮拿不到 1.0.3——本轮没重打包。他们下次打开还是 1.0.1 那份壳，
  要等下一次构建；源码跑的用户不受影响。

## 4. 接手后先做的三件事

1. `bash tests/run_all.sh` 跑一遍全绿（现在是 **40 项**：静态 20 + 真机 20），确认环境与
   基线。改前端只需重启浏览器（`ui.html` 每次 GET 都重读）；**改后端必须换进程**，
   这一轮的横幅就是为了这件事存在的。
2. 读 `platform_compat.py` 的 `port_verdict` 与 `ui.html:4243-4358` 那一段。任何新增入口
   （CLI、桌面壳、别的启动器）起服务前都得问 `port_verdict`，**不许再写「端口有人应答就复用」**。
3. 新增任何界面调用的 `/api/...`，先补后端路由再写前端；`tests/check_route_pair.py`
   会在静态门里拦住反过来的做法。真机套件一律通过 `bash tests/run_all.sh` 跑
   （它起沙盒并把地址传进去）——见 §5 最后两行那条踩过的坑。

## 5. 已知的坑（都踩过，写下来省下一次）

| 症状 | 根因 | 解法 |
|---|---|---|
| 点新功能只说「本机服务没在跑」，而服务活得好好的 | 界面把 404 与连不上揉成一句；真因是端口上挂着旧代码的进程 | `gzApi` 四类失败各说各的话 + 横幅写明两边版本 + `port_verdict` 判动作 |
| 三处各算一份代码指纹，永远判成「不一致」 | Python / Node / Swift 三份哈希口径不同，就是原地每次开都换一次进程 | 统一 `sha1(整个 ui_server.py 字节)[:12]`；`check_route_pair.py` 与 `test_backend_identity.py` 逐项对 |
| 换班其实成功了，界面却说「连接被对方掐了」 | 旧进程先退，那一瞬 `fetch` 撞空；另有一次是 `restart_backend` 里局部变量叫 `log`，把顶层的 `log()` 顶成字符串，下面 `log("…")` 当场 TypeError | 回执先送再退（延迟一拍）；变量改名 `logfile`；`GZ.swapping` 期间横幅不盖话 |
| 手动跑一份真机套件，把用户正在用的实例接管了 | `need_base()` 不给参数就缺省挂 8770，而 8770 正是用户那台归藏；MCP 那套还会 spawn 适配器，于是本轮新加的「接管」逻辑当场生效 | `need_base()` 现在没地址**直接退出**并说清怎么指沙盒；跑真机套件一律走 `bash tests/run_all.sh`（`selftest.py` 的 docstring 里写着这段事故） |
| 存完段落后按钮还红着「待存 3 处」 | `vtSave` 清了改动集，工具条要等后面 `await vtRefresh()` 才刷；机器忙时那一帧被拖长 | 清完立刻 `vtTools()`，回执与清零同帧 |
| 冒烟里 `book.move 归夹` 报「这个模块里没有这个文件夹」，看着像 bug | 后端认的是这本书自己住哪一格，故意不信前端传的模块标签（那个标签可能是上次刷新留下的）；夹具把文件夹建在别的格，**被拒是对的** | 夹具按这本书的 `module` 建夹，另加一条跨格被拒的断言把这句原因钉住 |
| 整轮门禁里偶发一个红，单独跑必绿 | 撞的是负载下的时序（防抖 + 回执覆盖 / 工具条晚一帧） | 复现要看负载；固定摆出断言（压住回执、清完立刻刷）而不是靠运气重跑 |
| 撤销点下去，那道线过一会儿又消失 | 存盘回执是「出发那一刻」的快照，`ntSave` 无条件拿它覆盖本地 doc | 每次 `ntTouch` 记 `NT.rev`；回执只在 `rev` 没动时才认；上一笔没回时新的一笔排队 |
| 套件里想「压住一个回执」摆竞态，结果时序全乱 | sync Playwright 下 Python 一 `time.sleep` 事件就不下发；延迟若连请求一起推迟，出去那份已带改动，什么也测不出 | 延迟放进页面里的 JS 定时器，**只推迟回执、请求照原样先出发** |
| 整轮门禁一片红（尤其 MCP 那两套），单独跑又全绿 | `tests/seed.py` 与服务用的 `GUIZANG_*` 不是同一套 | 四个变量（`GUIZANG_SELFTEST_DIR / GUIZANG_DATA / GUIZANG_BOOKS / GUIZANG_SHOT_DIR`）一起导出，铺书架和起服务用同一套 |
| 服务端口挪窝之后 MCP 找不着 | 服务从默认口往后找空位，而适配器只拿到「请它用的」那个数 | 绑到哪个口就把口写进 `runtime.json`，适配器认这个回执 |
| `GUIZANG_DATA` 设了之后仓库相对断言全错 | 一旦设了，`data_dir(repo)` 就不再等于传进去的 repo | 任何对 platform_compat 的仓库相对断言先清掉这两个变量 |
| flomo 重复导入出现「同一条两个 id」 | id 是 `sha1("时间\|正文")`，正文动一个字就成了另一条 | 存储里正文原样不动，标签与格式只在**交付时**清洗 |
| AI 小结半路断线后，上一次成品被空文件顶掉 | 「流没跑完」被当成「答完了」，照样落盘 | 落盘只在拿到完整内容之后；半路失败保留旧结果并如实说这次没成 |
| 栏名「看哪些」竖成一列 | flex 行里放**裸文本节点**，后面还跟着几颗钮 → 文本被压到只剩十几像素 | 标题包一层 `span` 配 `nowrap` + `flex:none`，行加 `flex-wrap` |
| 判「文字占了几行」判错 | `Range.getClientRects()` 把 `text-overflow:ellipsis` 那个「…」也算一个 rect | 用高度 ÷ 行高来数行；探针先自证抓得到真竖排 |
| dmg 打完了在仓库里找不到 | `make_dmg.sh` 不传参数默认丢桌面 | `bash shell/make_dmg.sh 安装包`（`开发规范.md` §8 就是这么写的） |
| 新增 `const st` 直接语法错 | 同一函数作用域里 `st` 已被「语音识别」占用 | 换名；inline JS 门禁当场抓出来 |
| 文档里的门禁项数过期 | 加减套件时忘了同步 | 项数写在 `开发规范.md` §7 与本文 §4；改套件就一起改 |

## 6. 版本与产物位置

- 版本号成对：`ui_server.py:58` 的 `VERSION` 与 `ui.html:4243` 的 `GUIZANG_PAGE` 都必须是
  **1.0.3**，`tests/check_route_pair.py` 守着这一条（不等就是「界面写给 A 版后端看、
  后端自己是 B 版」，横幅永远判不对）。
- **本轮不构建安装包**（用户明确要求）。`dist/归藏.app` 与 `安装包/归藏-1.0.1.dmg`
  是上一轮（1.0.1）的产物，本轮没有重打，README 安装段里那个链接仍指向
  `归藏-1.0.1.dmg` —— 这是**当前事实**，不是漏改。下一次打包时记得一起更新。
