## 1. 这一轮改了什么

### 更新内容

- **阅读 AI 独立配置**（`ai_*`）：设置里单独一栏；单独配了就各走各的，没配才沿用小 Agent。导图与流式小结都走 `ai_cfg()`（`agent_once(..., cfg=ai_cfg())`）。Key 回显只末四位；密码框白名单含 `aikey`。
- **阅读 AI 小结进右栏第三页签**：取消独立浮层；点「小结」后在 `.rdnotes` 第三栏加载，`.rdnotes.aiopen` 切换；可在当前页存为笔记 / 画导图。
- **氛围渐变可自定义**：六套预设 + 自定义色点与角度，与磨砂/模糊同一份 LOOK 落盘；默认色与旧色晕同色。
- **视频转笔记学生向布局**：步骤条、结果区标题、段落间距与书架可读性、空状态文案。

### 第二轮（UI 一致性 / AI 导航与内置浏览器 / 修复）

- **切页一致性**：`main` 的宽度收成一处 `--main-w:min(1440px,100%)`，撤掉按页另开宽度的
  两条口子，`html` 常驻 `scrollbar-gutter:stable`；视图常驻、只挪 `hidden`，交接动效第一次
  给足、回头客收一档。解决「前几屏正常、突然左右变动极大」。护栏 `check_pane_uniform.py`。
- **AI 导航 + 内置浏览器**：顶端正中「AI 导航」在归藏自己的 Chromium 系内核里开 `ai-bot.cn`；
  新增 `web_browse.py` 取回层（外站由本机取回、补 `<base>`、接跳转脚本再送进 iframe，
  绕开 `X-Frame-Options` / CSP）；安娜的档案那一栏也接了「内置浏览器」入口；下载仍自动入书架。
- **便签 memos 两栏**：左边随手记灵感、右边时间线看记录。
- **推荐页只六本**：数据切到 6、渲染不铺页头。
- **修复**：微信书架缺封面退到本地那口取一次；封面退路加 `keySet` 闸，没配 Key 不再空敲
  404（`f469d0b`）。小 Agent 认下几种「不标准回话形状」（整段 JSON / `message` 形 /

### 第六轮（1.2.2 · 油管那一页 + 界面七处，2026-10-16 合并）

用户报了七件事，四条是坏、三条是糙。**这一轮把版本号推到 1.2.2**（`ui_server.py` 的 `VERSION` 与 `ui.html` 的 `GUIZANG_PAGE` 同一笔改），**但没打新安装包** —— `安装包/` 里仍是 1.0.9 的 dmg / Windows zip，README 安装段照实写「当前源码 1.2.2、现成的包是 1.0.9（这一轮没打新包）」，链接仍指向真实存在的那两个文件。要出 1.2.2 的包走《开发规范》§8 第 5–7 步。

- **油管打开一片空白（或还看着像上一页的哔哩哔哩）**：根因不在取回，在 iframe 的
  `sandbox` —— 故意不给 `allow-same-origin`（不让外站读归藏的 localStorage），于是 YouTube
  那台纯客户端应用一碰 `localStorage` 就抛，回来的 HTML 只有一层 `<ytd-app>` 空壳。没有为它
  放宽权限，改成**自己读那坨 `var ytInitialData`**：按配对扫 JSON（字符串里的半个花括号不
  劈断）、新旧两代 renderer 都认、缩略图只引本站图床、视频 id 卡死形状，铺成一页归藏自己的
  静态目录（封顶 24 支），链接照旧走 `/api/browse`，每支旁边一颗「转成笔记」直接回视频那屏
  开跑。缺的只有播放器（流式媒体这一层从来不代理，见 §2 风险）。落点：`web_browse.py` 的
  `is_youtube` / `_json_after` / `_yt_cards` / `_yt_page` / `yt_static` / `shape()`，界面
  `vidUseLink()`。顺手把「同一地址不重发」那层的遮罩残留一并守住（`.bzload` 是不透明的）。
- **上面这条修完，用户第二次报「依旧打不开 / 页面取不回来」** —— 是同一件事的第三层根因，
  2026-10-16 当晚补上。未登录的 youtube.com **首页与几个 feed 页连那坨 JSON 里都不放内容**：
  实测首页 950KB 里 `videoId` 出现 0 次，正文只有一句「搜索视频，开启 YouTube 之旅」（真浏览器打开
  也一样，不是我们取漏了；`/feed/trending`、`/gaming`、`m.youtube.com` 同理）。取回来是成了、静态目录

  （`export_precise._atomic_write_text`）也换成随机名，于是这一刀会当场瞎掉。这是第十一轮就在 §2
  预登记的那条耦合（「等那一处换成随机临时名，`drop_stray_md` 也得跟着换成按形状扫」），
  **同一个 PR 里就地还上了**：候选集从 `{<名>.md, <名>.md.tmp}` 扩成「再 `listdir` 这一层目录，
  把以这本自己的 `<名>.md.` 开头、以 `.tmp` 结尾的都算上」——只在这一层、不递归、不跟链接，
  前缀收到「这本自己」是为了别家书的合并稿残件一个都不许误伤。门禁 `tests/check_export_tmp_name.py`
  的 E 节钉的就是这一面，并带一条「老那把刀两份随机名残件一个也没收走」的对照。
- **`cache/` 与数据根上写到一半的账本，归「清除本地数据」那一刀管**（第十七轮 `#172`，
  门禁 `tests/check_cleanup_tmp.py` 22 条）。`cleanup.run()` 原先按**精确路径**删白名单里那两张表
  （`CACHE_FILES` 15 项 + `ROOT_FILES` 3 项），而各本账的落盘都是「先写同目录临时件再 `os.replace`」，
  改名之前被强杀就留下一份半截账：`<账本>.<pid>.<8位随机>.tmp`（现版尺子）或 `<账本>.tmp`
  （`login` 那一处、以及各格改名之前留下的）。两种形状一个都不在精确名单里，于是点完「清除本地
  数据」界面回「已释放 …」，半截 `config.json` 还躺在盘上 —— **那里面就是用户的接口 Key**，
  而这一刀正是换机、把机器送人之前最常点的那一下。现在按同一张白名单逐名去找它的 `.tmp` 兄弟
  （`_residue_re`：`^<name>(?:\.tmp|\.\d+\.[0-9a-f]{8}\.tmp)$`，前后锚死），试算里如实列出、
  真清时一并删掉；不认识的 `.tmp`、同名目录、符号链接一概不碰。
  **还剩一格没收（本轮审覆盖面时数出来的，不是 PR 报的）**：`sync._write_atomic`（`sync.py:487`）
  取回远端文件时先写的是 `<目标>.part`，而 `_collect`（`sync.py:451`–`463`）把 `cache_dir` 里的
  账本（`readstat.json` 与那几个 `what` 点名的档）也列进同步对 —— 于是同步中途被强杀，
  `cache/` 里可能留一份 `<账本>.part`，而这一刀的尺子只认 `.tmp` 两族形状、`drop_stray_tmps`
  只扫书目录，两处都够不到它。要收就是把 `_residue_re` 的后缀并进 `.part`（书目录那一头已经
  是 `.tmp` / `.part` 同一把尺子，`STRAY_PART_SUFFIX`），并给 `check_cleanup_tmp.py` 补一条
  `.part` 的形状。**本轮没动它**：它属于「同步」这一格，与这一批的六条都不沾，且改的是清理白名单
  的判据（红线那一面得多钉几条才敢动）。
- **「用户能直接改的文本」读口认 BOM 这一族还剩两处**（第十轮 `#151` 审出这一族、第十三轮 `#162`
  收到视频那一格、第十七轮 `#175` 收到取书那四本账；下面这两处是本轮**审覆盖面时自己数出来的，
  不在任何 PR 的报告里**）。判据仍是那条：记事本「另存为 UTF-8」多塞的那三字节只坏在**读**的那一侧，
  所以写口一律照旧 `utf-8`、读口一律 `utf-8-sig`。剩的两处：
  ① `clip_article.save_clip`（本轮实测 `clip_article.py:976`）—— 它把刚由 `book_import` 建好的
  `meta.json` **内联**读回来补剪藏字段，用的是裸 `utf-8`，外面罩着 `except Exception: meta = {}`，
  紧接着 `meta.update(...)` 再 `_write_json_atomic` 写回 —— 带 BOM 时读回空 dict，等于**以空账为底
  重写那份 meta**，用户改过的其它字段整份丢掉。代价要说清：这一处读的是同一趟里 `book_import` 刚写的
  那份，而剪同一个 URL 每次开的是**新书目录**（第十六轮 I5 实测过），真撞上 BOM 得有人在那两句之间

## 3. 怎么验收

1. 设置 → 阅读 AI：单独填地址/模型后，小结与导图不改小 Agent 三项。
2. 打开一书 → 右栏「小结」页签：结果在第三栏，不弹独立窗；可存笔记 / 画图。
3. 设置 → 外观：换氛围预设 / 自定义色点，刷新后仍在。
4. 视频转笔记：看得见三步提示与结果区标题；贴一个长视频链接，翻屏不卡、进度条实时走、
   刷新后左栏仍有「转写中」、点停止立刻回「正在停…」。
5. 点顶端正中「AI 导航」：在归藏自己的内置浏览器里打开 `ai-bot.cn`，点页面里的链接仍在
   这一屏里往下走。
11. 画板：这一屏铺满整窗。左栏切到「换一本书」能挑另一本；点书名的正文浮在画布右下角，
    滚轮滚正文时不带着画布跑。按住拖动（或滚轮 / 触控板双指）把画布挪到任何地方，
    纸上画的笔不动；⌘/Ctrl + 滚轮绕手势中心缩放；按工具条那颗「按内容置中」能回到这块画的东西。
    关掉再开，位置回到纸的左上角而不是上次挪到的角落。
12. 写作台：工具条是一行图标（粗 / 斜 / 下 / 删 / 码 / 字色 / 底色 + 段落样式一颗 + 「+」），
    不折行、不堆叠。段落样式那颗显示的是光标所在那一段的样式，切到引用里它跟着换成引用的图标。
13. 视频转笔记：转写结果是一张张卡片，不是带横线的表格行；时间戳与说话人在同一行。
14. 订阅左栏：「看哪些」与右侧那几颗钮左右分区，标题不歪。
6. 便签那一格：左边用工具条敲一段富文本，右边时间线立刻看得到；复制出去是 Markdown，
   卡片上「复制」拿到的也是 Markdown。
7. 剪藏那一格：复制一条文章链接，点手指圆钮，外圈环走满后弹「解析已完成」，文章在下方列表。
8. 思维导图：节点不再挤压，小框对长文字自适应完整显示；触控板两指捏合 / 触摸屏双指捏合
   能绕手势中心缩放，没有加减号钮。
9. 推荐页：只有六本，六本上方没有任何文字；每张卡下方有「加入书架」，点了写回微信读书。
10. 左侧逐格点过去：每一屏左右边一致，不横跳；在阅读器里选一段问小助手，几家上游的
    非标准回话形状也不该显示成「断线」。
11. 微信书架里取回的部分书封面（外站图床）能正常显示。
12. 划线笔记：书籍卡片瀑布流；取书时在本机划的线也在墙上，点进去与微信条目混排。
13. 随机漫步：顶栏三档切到「取书」，抽到的是本机读书笔记，徽章换色。
14. 安娜的档案：只有搜索框 + 搜索键，输入书名点搜索或回车，窗口自动领到搜索结果页。
15. 取书：取到一半的书也能点「阅读」先读，旁边有「续取」；任务不再卡在「正在取」。
16. 书架切叠卡，连续快翻十来本，不卡顿、不闪烁。
17. 任意按钮按下去有反馈（缩放 / 落点涟漪），系统开「减少动态效果」后这些反馈关闭。
18. 关于 / 页顶版本为 1.2.2。
19. 第八轮那三件都能自己动手验：① 手改 `cache/plan.json`，把某天的读数写成带引号的超长
    数字串（`"10000000000…"`），刷新后计划那一格读到的仍是同一个数（不是 0）；② 在某一本书
    `raw/*.json` 的插图清单里塞一条 `file:///etc/hosts`，重跑导出收尾，`images/` 里不会多出
    任何本机文件的内容，日志那句说的是「坏记录跳过」；③ 封面不再出现「下载成功了却没落上、
    旁边留一个 `.tmp`」或「永远打不开的半张破图」，`cache/covers/` 里不该有 `.tmp` 残件。
20. 第九轮那三件同样能自己动手验：① 正常 EPUB 照旧导入，再手搓一份坏的——在 OPF 的
    `<package>` 前面垫一段几万字符的注释、注释后面写 `<!ENTITY` 声明，导入不炸也不撑内存，
    章节按 manifest 排出来（旧写法会把这段声明顶出窗口放过）；② 拿一个自己控得住的页面，
    在里面写 `<link rel="alternate" type="application/rss+xml" href="file:///etc/hosts">`，
    界面上点「发现订阅」或直接跑 `.venv/bin/python feed.py <那页地址>`：坏地址不进候选列表，
    加订阅与刷新也不会把本机文件读回来（`feed.json` 里手塞一条 `file://` 再点刷新，同样被挡）；
    ③ AI 小结生成到一半把后端强杀，重开后那一格还是上一次那份完整小结，不是断在半句的那一截，
    `_ai/` 里也不该留 `.tmp`。
21. 第十轮那三件同样能动手验：① 往剪藏框粘一条 `http://%31%32%37.0.0.1:8770/api/state`
    （或 `http://192.168.%31.1/`），回的那句是「这是本机或内网地址，归藏不替你访问」，而不是把
    本机服务的 JSON 剪成一篇文章（旧写法这道闸认不出编码过的写法）；② 用文本编辑器把写作屏那本
    `_books.json` 另存成「带 BOM 的 UTF-8」，刷新界面书目照旧在，再建一本新书后旧书目不丢、
    写回的文件开头也没有 BOM；③ 便签那一格连着快速点两次手记 / 打标签，`cache/flomo/` 里不留
    `.tmp` 残件，账本也不会突然退回空的（界面=「便签全没了」）。
22. 第十一轮这三件也都能动手验：① 取一本长书，翻到一半按停止键再等它超时被强制结束（或直接
    杀掉引擎进程），回书库那一章要么整个不在、要么是完整的一章，不该出现「章名在、正文缺一半」
    的那份；重跑同一本，那一章会被补上（旧写法它会被续传当成已写出来）；② 同一本书同一范围
    连点两次 AI 小结（同步那条与后台任务那条一起跑），两次都该回「存好了」，`_ai/` 里那份是
    完整的某一份、不是两份混在一起，也不留 `.tmp`；③ 一块板开两个窗口同时画（或一边画一边导
    PNG），两边都该提示存上了，`boards/` 里不留 `.tmp` 残件；之后删掉这块板，`purge` 会把
    带随机串的残件一并收走（旧写法只认那一个固定名）。
23. 内置浏览器进 YouTube：认不出卡片时换一处有货的落脚点（搜索结果 / 音乐页），页面副标题
    讲清为什么换；带着用户自己敲的搜索词的那一页不换；空搜索照换。
