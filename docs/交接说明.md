## 1. 这一轮改了什么

### 更新内容（新长出来的东西）

**写作不再要求手写 Markdown —— 正文上方一排工具条（`ui.html`）**

`WR_TOOLS` 现在有 21 颗钮（4 道分组分隔、1 个弹性位）：
正文 / 标题一二三｜加粗 / 斜体 / 下划线 / 删除线 / 行内码｜字色 / 底色 / 清格式｜
无序 / 有序 / 待办 / 引用｜表格（点几乘几就插几乘几）/ 链接 / 图片 / 分隔线｜「看 Markdown」。
两颗前提必须钉住，否则按钮点了等于没点：

- **选区不能被点丢**。按下任何一颗之前先记住用户选到哪儿（`WR.range`），动手前把选区放回正文
  （`wrFocusRange`）；所有浮层一律 `pop.onmousedown = ev => ev.preventDefault()`，否则选区先被
  这一下清掉，颜色就涂到光标那一个字上。
- **看得见的是排版，存下来的是 Markdown**。正文与 Markdown 之间是双向翻译（`wrParse` 读、
  `wrGet` 写）；斜体那条「星号是强调还是字面意思」的判据**不能抄后端**——`book_export` 用的是
  环视断言，WebKit 不支持后视，所以前端改成在替换回调里看左右邻居（`wrInline`）。

**左栏改成「书 → 第一章 / 第二章」那棵树（`writer.py` + `ui_server.py`）**

- **只挪号，不搬文件**。章节仍是原来那篇稿子；`书库/写作/_books.json` 一份账记「书号
  （`bk_` + 12 位十六进制）→ 章的稿号列表」。删册只散册，一篇稿子都不会少；一章只属于一本书。
- 后端 `writer_do()` 现在管 **13 个动作**（POST body 里的键是 `do`）：原有的
  `create` / `rename` / `versions` / `snapshot` / `restore`（外加 `save`），加新的七个
  `book.create` / `book.rename` / `book.delete` / `book.add` / `book.remove` / `book.order` / `book.merge`。
  对不上号时程序不瞎改，回执里指路该用哪颗钮。

**MCP 56 → 61 颗，十一类 → 十二类（`mcp/guizang-mcp.mjs`）**

新增一类「书写」5 颗：`writer_books` / `writer_book_new` / `writer_book_rename` /
`writer_book_chapter` / `writer_book_delete`。个数以 `tests/check_mcp_tools.py` 现读服务端的
`tools/list` 为准 —— 文档里写死的数必须跟着代码走（这一轮把 README / 部署说明 / 架构与模块地图 /
开发规范里写死的 56 全改成了 61）。

**富文本标记能活着走出导出（`book_export.py`）**

`book_export.py` 现在明确只有一个渲染出口：取来的书、写作页的稿子、导出的四种格式全过
`md_to_html`。工具条写的三种内联标记（字色 / 底色 / 下划线）走**白名单**，只认 `_SPAN_OPEN`
那一种形状（属性名二选一 + `#hex` 色值）；稿子里手打的其它尖括号一路留在转义态，导出后仍是
看得见的文字，不会变成能执行的东西。待办勾与表格也补齐了三份样式表里的长相。

**两套新静态门禁（`tests/`）**

- `check_writer_book.py`：建书 / 归章 / 排顺序 / 坏账本 / 合稿 / 摊成一本真书（含真打 EPUB，
  确认章节顺序按册账走，不是按目录里谁新谁旧）。
- `check_rich_export.py`：白名单里三种标记、白名单之外一律留转义态、待办与表格、三份样式表、
  四种排版各渲染一遍，最后真打一个 EPUB 并验包里 `mimetype` 是首条目且 STORED。

### 优化项（原有的东西改好）

**取书那条**：`export_precise.py` 的续传口径整个重写（也修了 bug，见下节）。

**写作这一屏的视觉与手感**（沿用界面已有的那套口径，不新造一套）：
书树整行可点、展开箭头走弹簧曲线转正（`--spring` = `cubic-bezier(.32,.72,0,1)`，`.open` 时
`rotate(90deg)`）；章列表出现走 `wrUp`（`.24s`，从下方 8px 淡入）；合着时才在行尾显示「几章几字」，
展开就收掉；稿子卡按下去缩到 `.985`；**正面板保持不透明**（`background:var(--paper)`，上一轮定过：
稿子上铺磨砂会把字和玻璃糊在一起），聚焦时给 3px 强调色外圈；工具条不新写样式，复用笔记编辑器
那一套 `.edtools`（同一支钮、同一个 `.on` 态）；`display:flex` 又能挂 `hidden` 的都配平
`.xxx[hidden]{display:none}`。

**静态体检加了一条硬规则**（`tests/check_js_refs.py`）：同一个内联脚本的最外层不许有两份同名
`function`。函数提升时后一份会静默顶掉前一份，编译器不报错、浏览器不报错，只有走到那条路才炸
（见下节那条笔记空状态事故）。缩进里的函数关各自的作用域，撞名合法，所以只看行首那一份。

**文档同步**：README、部署说明、架构与模块地图、开发规范、交接说明五处按代码实测值改齐
（工具数、路由、状态对象名、动作键、模块行数、门禁项数）。顺手抓到 README 一处从 1.0.7 起就写错的
话（「十二个入口……五个工具」，实际 `NAV_ITEMS` 是十三格）；`架构与模块地图.md` 里 29 行模块行数
逐行用 `wc -l` 复核，无过时项。

### 修复项

**1. 有些书取到一大半就停，重取每次卡在同一处（就是用户点名的那个）**

根因不是网络，也不是那本书读不出来，是**续传落点信错了东西**：引擎看的是阅读器自己记的
「上次读到」（目录跳转不更新它），一轮跑完就收工；那个位置停在一个再也翻不出新章节的点上，
落点永远不变，于是每一轮都在同一处卡死。按实测那本书算：139 个缺项里 126 个是真漏，
旧口径返回的落点却已快到目录末尾（第 220 项）—— 那是一条死路。改成三件事：

- **落点由目录钉**（`resume_catalog_index`）：每轮钉在「目录里第一个还没写出来的那一项」，
  缺口散在中间就回到最早的缺口，开头缺章也钉回第一项。这样每一轮必然往前推进。
- **回填不许重抄**（`ChapterSplitter(gapfill=True)`）：走过一段已经写过的内容是这一轮的常态，
  走旧内容时只丢不写，遇到第一个没写过的标题才放出来，落点那一页不当边界看（页眉可能挂着旧章名）。
- **真跳不过去的就绕开**（`stuck_skip` / `_stuck.json`）：某一轮钉在某个缺口却一章都没写出来，
  就给那一项记一次；连着 `STUCK_LIMIT = 2` 轮钉不住才认定它跳不到、以后不再钉它。只试一次就跳
  会把「浮层挡了一下」「网络抖一下」误判成永久缺陷；一次都不跳又会让下一轮钉回同一个死点。

`tests/check_resume.py` **37 项**钉住这三件事。

**2. 笔记读取失败时空状态整块画不出来（`ui.html`）**

同一个内联脚本里有两个 `ntEmpty`：一个管「给一份空文档」，一个管「往容器里铺这句为什么是空的」，
后者签名两个参数、不传参什么都不回。JS 只认名字不认用途，于是前者的三个调用点（`d.doc || ntEmpty()`）
拿回 `undefined` 而不是空文档，紧接着读 `.marks` 抛 TypeError。界面当时看着一切正常 —— 到处都是
`NT.doc && …`，画得出来；真机走查走不到那条错误分支。已拆成两个名字，并把「最外层不许同名」
固化成静态规则（见上节）。

**3. 一处文档谎话**：README 的入口数（实际十三格，漏写了「安娜的档案」），已改。

## 3. 还没验过的（诚实清单）

- **取书那套修复是离线取证 + 真机门禁验的，没有拿用户那本真卡住的书重跑一遍完整链路**
  （要账号、要联网）。判据来自 `check_resume.py` 那 37 项续传断言和目录 / 落盘的模拟。
  第一次拿它取一本曾卡住的书时，值得盯一眼进展栏里有没有「钉不住，跳过」这类话。
- **旧稿不会自动归进某本书**：写作的新三层结构（书 / 章 / 稿）只改账本、不动文件，旧稿子全部照旧
  可读，但要在界面上自己归第一次。
- **Windows 那个分发包仍没在 Windows 上开过一次**：装（复制 + 桌面快捷方式）与跑（建环境 / 装依赖 /
  下 Chromium / 开界面）整条路只有「脚本按 Windows 的规矩写」这一层把握。
- **云端转写只填了地址、没对具体厂商真联调过**（1.0.8 起的老账）：准不准取决于用户选的模型。
- **划线笔记导出 CSV 只在 flomo 网页版导入页对过字节格式**（1.0.8 起的老账）：没真拿一份导出件
  去 flomo 里点过一次「导入」。
- **真账号那一段没走过**：安娜的档案下载要先登录，只在沙盒 + 本机夹具上端到端跑过。
- **界面这几条真机套件只在 Chromium 上验过**；Safari 没实测。
- **逐屏切换那个 79ms 长任务**：定位过，是暖态下的首次布局（首屏要铺一批卡片），不是回归、
  也不是可稳定复现的争抢；没有为它加人为等待。
- **`code_disk` 认的是 mtime + size**：内容变了而这两样都没变（极少）就认不出来。
- **时长账（学习 / 写作两张热力图）的停靠口径**：靠界面心跳上报，没有在长时间挂机场景下核过对。

## 4. 接手后先做的三件事

1. `bash tests/run_all.sh` 跑一遍全绿（现在是 **57 项**：静态 28 + 真机 29），确认环境与基线。
   改前端只需重启浏览器（`ui.html` 每次 GET 都重读）；**改后端必须换进程** —— 页顶横幅除了版本号
   还会看 `code_disk`，「改了后端没重启」瞒不住。**跑真机套件时别同时改 `ui.html`** —— 真机套件
   从磁盘现读，边跑边改会读到半份。
2. 要碰取书续传，先读 `export_precise.py` 的 `resume_catalog_index()` / `stuck_skip()` /
   `ChapterSplitter` 的 `gapfill` 口径，再读 `tests/check_resume.py` 那 37 项 —— 那里面写清了
   「为什么落点必须由目录钉、为什么不能只试一次就跳」。**别再改回「信阅读器上次读到」那套。**
3. 要碰写作的语法，记住**语法集合有两份**：界面那套（`ui.html` 的 `WRE` / `wrParse` / `wrGet`）
   与导出那套（`book_export.md_to_html` 及其白名单），改一边必须改另一边，否则「屏幕上好看、
   导出去变文字」或反过来。`check_rich_export.py` 与 `check_writer_ui.py` 各钉一半。

## 5. 已知的坑（都踩过，写下来省下一次）

| 症状 | 根因 | 解法 |
|---|---|---|
| 取到一大半就停，重取每次卡在同一处 | 续传落点信的是阅读器自己的「上次读到」（目录跳转不更新它），外层一碰到本轮 0 章就收工；旧口径「最后一个已写出项的下一项」在那种书上算出来是目录末尾附近，每轮钉在同一个死点 | 每一轮都由目录钉「第一个还没写出来的项」，路上重读到的旧章节走 `gapfill` 丢掉不重抄，连着两轮钉不住才记进 `_stuck.json` 跳过它；`check_resume.py` 37 项钉住这三件事（本轮） |
| 笔记读取失败时，空状态整块画不出来 | 同一个内联脚本里两份同名 `ntEmpty`，后者把前者顶掉：要空文档的那三处拿回 `undefined`，读 `.marks` 抛 TypeError；界面看着一切正常（到处都是 `NT.doc && …`） | 拆成两个名字；`check_js_refs.py` 新增「最外层不许同名函数」硬规则（本轮） |
| 写作页把稿子里的 `<span style=…>` 原样导出成文字 | 页面存的是真 HTML，导出第一步把整行转义了；白名单模式要是照**原始**尖括号写，永远命不中 | 白名单里的模式写成「转义后」的形状（`_SPAN_OPEN` 认 `&lt;span style="…"&gt;`）；其它尖括号留在转义态（本轮） |
| 点工具条上的颜色，涂到了光标那一个字上 | 浮层上的按下一落到正文，先清掉了选区 | 浮层 `onmousedown = ev => ev.preventDefault()`；动手前 `wrFocusRange()` 先把选区放回去（本轮） |
| 斜体判据搬去前端就失灵 | 后端用环视断言（`(?<!\*)`），WebKit 的 JS 不支持后视 | 前端改成在替换回调里看左右邻居（`wrInline`），不抄后端那条正则（本轮） |
| 落盘的 CSV 里混着裸 LF | `csv` 模块只按 `lineterminator` 收行尾，字段内部原有的 `\n` 原样进引号 | 落盘前 `_crlf()` 把正文换行也归一成 CRLF；`check_notes_csv.py` F9b 钉住「整份通篇 CRLF」（1.0.8） |
| MCP 那句「云端转写已就绪」是假绿灯 | `available().asr.cloud` 只是「这条路在代码里可用」的能力位（云化后恒真），拿它当「配好了」 | 要报的是用户填没填地址：读 `v.asr.url`，没填就说没填（1.0.8） |
| bootstrap 的步骤标签半截对不上 | 删了第五步，标签还写着 `[1/5]…[3/5]`，末步却是 `[4/4]` | 标签统一成 `/4`；`check_asr_cloud.py` W3 加断言（1.0.8） |
| 老配置写着 `mlx` 却当成云端跑了 | 引擎挑选静默改道 | `pick_engine()` 对非 `auto/cloud` 直接报「本地转写已移除」并指路设置（1.0.8） |
| 左侧导航少了新增那一格，界面却不报错 | 页面每次现读磁盘、名册装在进程里，本机跑的还是旧进程；而两个版本号一样，旧判定只比版本号所以无声 | 后端多报 `code_disk`，界面把「码不相等」也当过期；`check_swapbar.py` 1b 钉住（1.0.7） |
| 窗口能开，但站点一直打不开 / 一下就 513 | 对方 WAF 在 TLS 层挡机器请求：无头 Chromium 与 `urllib` 都被顶回来 | 有头窗口是正确性要求；代理显式挂给浏览器（`--proxy-server`）（1.0.7） |
| 嵌进界面那一屏是空白的 | 页面带 `X-Frame-Options: SAMEORIGIN` | 不做内嵌；做成「工具自己开窗口」（1.0.7） |
| 关键词递过去了却没搜 | 搜索参数名猜的是 `term` | 实测是 `q`；`search_url()` 里钉死并写了注释（1.0.7） |
| 一点下载整个窗口卡住 | 立即触发下载的页面永远不 fire `load`，`wait_until` 用默认值就干等 | 用 `wait_until="commit"`（1.0.7） |
| 归藏自己的界面反而打不开了 | 起浏览器时继承了系统代理，`127.0.0.1` 被代理吃掉 | 该窗口对 localhost 走 `--no-proxy-server`（1.0.7） |
| 同名文件把已入库的那本盖了 | 站点同名条目多，直接写同名 | `save_as` 同名加时间戳；入库另按字节摘要去重（1.0.7） |
