# book-speedrun：一本书速通

## 这个 skill 干什么

用户拿来一本书——给文件、给书名、或直接说「速通这本书」——一次交付把它讲透：先给地图看清骨架，再分块讲核心，再一条线连讲一遍，最后压缩成一页速记加行动清单。讲义每块末尾挂一条当场能做的动作。

核心区别：**一次交付，不连载**。读完这一个输出，用户应该能跟人聊这本书、能上手用它，不需要再读第二遍。

## 与已有 skill 的分工

| 用户想要 | 走哪个 |
|---|---|
| 一次讲透一本书，读完即用 | **本 skill** |
| 一章一篇慢慢读，写反馈、进知识卡片、长期积累 | `grace-coach` |
| 把书做成可追溯知识库 + 交互式学习网页 | `learn-from-materials` |
| 学一个主题（不一定是书）的通用导师陪练 | `learn-anything-skill` |

判别信号：用户说「快速熟悉」「快速掌握」「讲一遍」「讲透」→ 本 skill；说「带我读」「继续下一篇」→ grace-coach。

## 第零步：摸清输入

| 输入形态 | 怎么处理 |
|---|---|
| 文件（PDF / EPUB / DOCX / TXT / MD） | **读它**。以文件内容为唯一事实来源 |
| 只有书名 | 用训练知识讲，**开场必须声明未核对原书** |
| 网页 / 长文链接 | 抓取正文后按书处理 |
| 模糊指代（说「这本书」但没给） | 问一次：「书名或者文件给我一下」 |

**读完再讲，不许猜。** 文件读不了（加密、扫描件无文字层、格式不支持）直接说，回落到训练知识并标明。扫描件需 OCR 时如实说明代价，不假装读过。

**不追问，先动手。** 除非输入不足以开始，否则不提问。需要定用途时，在第一次输出里用一句话带过：「我按『能上手用』的方向讲，你要是有具体用途（考试 / 工作 / 写作），说一声我调。」

书特别厚（500 页以上）或用户明说只关心某部分时，先问一句要不要只速通指定部分，或改走 `learn-from-materials`。

## 硬规则：不许编书

讲书最大的坑是幻觉。以下四类信息**只许来自实际读到的内容**：

1. 页码、章节号
2. 加了引号的原文
3. 具体数字、日期、人名、案例细节
4. 「作者在第 X 章说」「书里举了个例子…」这类定位断言

没有原书、靠训练知识讲时，开场写一行：

> 以下基于模型训练知识整理，未核对原书。页码、精确引文和具体数据不要直接引用；我记不准的地方会标出来。

把握程度分三档，用在具体事实旁边：

- 有原书依据 → 直接写，必要时标（第 X 章）
- 训练知识里明确 → 直接写
- 记不准 → 标 `[记不准]`，不含糊过去

宁可少说一句，不要多编一句。用户拿这本书去引用的时候，编的那句会让他丢脸。

## 输出：四段式

固定四段，顺序不变。这是速通，不是全解——**宁可短，不要水**。

### 第 1 段 · 前导地图

30 秒看完这本书，回答四个问题：

1. **一句话主线**：这本书在回答什么问题？写问题，不写「讲了什么」。
2. **骨架**：推进路线 3–7 个台阶，每台阶一句话。用文本树或 mermaid 画，不要大段文字。
3. **概念坐标**：核心概念 5–12 个，标出每个落在哪个台阶、跟谁相连。
4. **怎么读 + 读完的判据**：哪几章是主干、哪几章可以跳、建议读法；读完这本书你应该能做什么（3 条，要具体）。

长度 ≤ 400 字（不含图）。

### 第 2 段 · 核心讲义

按骨架的台阶分块，一块一个小节，每块固定五项：

- **核心命题**：一句话，加粗
- **怎么推的**：论证链，去废话。这是讲义主体
- **书里的例子**：用书里的；书里没有就写「书里没给例子」，不要自己编一个冒充
- **容易搞错**：这一块最常见的误解或边界
- **【动手】**：当场可执行的一条，写法见下节

块数 3–7，别硬凑。重点标 ⭐，**全篇 ⭐ 不超过 5 处**——标多了等于没标。

每块 ≤ 500 字。

敢砍：铺垫、重复、过时内容、作者啰嗦的段落，直接写「这块可以跳，一句话说就是……」然后一句话说完。

### 第 3 段 · 全书串讲

**一条线讲完，不分小标题。** 这是密度最高的一段，目标是把前两段散落的东西串成一条能被复述的线。

- 口语，像懂了的人给你讲，允许转折、类比、吐槽
- 允许说「这里作者其实绕了」「这一章放在这个位置有点奇怪」
- 串讲是重新组织，不是复述讲义措辞
- 长度 800–1500 字，一口气能读完

### 第 4 段 · 带走

**一页速记**：全书压成 ≤ 10 条，一条一行，日后翻这一页就够。

**行动清单**，按时间分三层：

- **今天**：10–30 分钟能做完的
- **这周**：需要几天持续的
- **用完之后**：把这本书变成长期资产的动作（比如把这个框架套到手上的某个具体项目上）

## 「当场可执行」的写法

本 skill 最容易做砸的部分。判据三条，缺一条不算，讲义里那块就不合格：

1. **有动作**：动词开头，是一个具体操作
2. **有时长**：几分钟 / 几小时，写清
3. **有完成判据**：做到什么程度算做完

反面例子（写了等于没写）：

- 「多思考一下这个概念」——没有动作、没有判据
- 「深入理解作者的观点」——同上
- 「把这个方法用起来」——没有具体对象

正面例子：

- 「打开你手上那篇没写完的稿子，用书里的『先给结论』原则重写开头三句，15 分钟，标准是陌生人读完前两句就知道你要说什么」
- 「挑最近一次和别人的争论，按书里的『区分事实与判断』拆一遍，写三行：哪些是事实、哪些是判断、分歧卡在哪，20 分钟」

动作要贴着用户的真实场景写。不知道用户场景时，用大多数人手上都有的东西（一段没写完的文字、一次刚发生的对话、手机上某个耗时 App、手头一个拖着没做的决定）。

## 写作红线

**禁用句式**（交付前跑一遍 grep 自查，别靠记性——实测过好几次「列在这里了照样写出来」）：

```bash
grep -n "不是.*而是\|真正的.*是\|与其说.*不如说\|不在于.*在于" <输出文件>
```

命中就改写。

其他：

- 简体中文，用「你」不用「您」
- 中英文之间、中文与数字之间加空格
- 不写「首先 / 其次 / 最后」「综上所述」这类支架词
- 不写空泛鼓励，不复述用户原话开场
- 干货的标准：删掉它，理解会缺一块。达不到就删

## 输出位置与形态

默认**在对话里完整给出**——这是速通，即读即用。

用户说「存下来」「做成文档」「发我」时再落盘：

- Markdown / Word → 桌面（用户的默认交付位置），Word 生成后补渲染检查
- 要成体系、带交互的学习页 → 转 `learn-from-materials`

## 交付前自检

- [ ] 四段齐全，顺序正确
- [ ] 每块都有【动手】，且满足「动作 + 时长 + 判据」三条
- [ ] 没有编造的页码 / 引文 / 数据；无原书时开场已声明
- [ ] ⭐ 不超过 5 处
- [ ] 串讲段是一条连贯的线，不是小标题拼接
- [ ] 禁用句式 grep 通过
- [ ] 通读一遍：删掉一半会不会更清楚？会就删
