# guizang：用自然语言操作本地微信读书工具

## 这个 skill 干什么

归藏是一个跑在用户本机的微信读书工具：能把整本书导出成逐章 Markdown（图文按阅读顺序交错）、管理本地书架、检索用户自己的划线与想法、导出 Anki 卡包、把书加进用户的微信读书书架。它通过一个本地 MCP 服务器暴露一整套工具；本文件只覆盖「取书 + 划线 + 归架」这条主线常用的那些，订阅、视频、思维导图、画板、便签、写作各有自己的工具 —— 以本会话里 `tools/list` 现读到的清单为准。

本 skill 负责把这些工具用对：**先看清状态，再动手；长任务不阻塞；写操作只做用户明确要求的那个。**

## 前置检查（第一次用时先做，别跳）

1. **MCP 是否接好**：本会话里应当能看到 `mcp__guizang__*` 的工具。看不到就让用户按仓库 README 的「接入 AI Agent（MCP）」配一次，配完**重启 Agent**（MCP 是启动时加载的，不能热加载）。
2. **调一次 `app_status`**：它会告诉你运行组件是否就绪、微信读书是否已连接、当前有没有任务在跑。
3. **没连接** → 用 `account_connect` 唤起扫码窗口，并**明确告诉用户「请在弹出的浏览器窗口里扫码」**——这一步需要真人，你等不到结果，别轮询。
4. **书架是空的** → 通常是没填接口 Key。让用户在界面「设置」里填微信读书网页版的开放 API Key（形如 `wrk-…`）。

地址、端口、项目目录都别猜：适配器自己知道，你只管调工具。

## 工具地图

| 想做什么 | 用哪个 | 记住 |
| --- | --- | --- |
| 看状态 / 有没有任务在跑 | `app_status` | **任何操作前先调它** |
| 看任务跑到哪了 | `task_log` | 取书进行中靠它看进度 |
| 列本地书架与文件夹 | `shelf_list` | 拿书的 id 用；含章节数/字数/是否收齐 |
| 搜东西（本地 / 划线 / 书城） | `search_books` | `scope` 传 `all`/`local`/`notes`/`store`；**找书先用它** |
| 看一本书的完整信息 | `book_detail` | 简介、进度、划线数、本地是否已取回 |
| 取一本书到本地 | `book_fetch` | **立即返回**，见下方硬约束 |
| 一次取多本 | `batch_fetch` | 一次只跑一本，跑完再调一次取下一本 |
| 中止取书 | `task_stop` | 已取回的章节保留，可续取 |
| 拿导出产物的路径 | `book_files` | 给用户路径，别把整本内容贴进对话 |
| 建笔记索引 | `notes_index` | `notes_search`/`notes_random`/`apkg_export` 的前置 |
| 搜自己的划线与想法 | `notes_search` | 先建索引 |
| 随机抽几条旧笔记 | `notes_random` | 回顾、举例都合适 |
| 导 Anki 卡包 | `apkg_export` | 返回 `.apkg` 路径与卡片数 |
| 多本打包成 ZIP | `zip_export` | 返回文件路径 |
| 打本地标记（待读/在读/已读） | `book_mark` | **只改本机归类，不动微信读书** |
| 把书加进微信读书书架 | `shelf_add` | **写操作，见下方硬约束** |
| 本地书架归类 | `folder_create` / `book_move` | 建文件夹、把书移进去 |
| 删本地缓存 | `cache_delete` | 默认只列不删，要 `confirm: true` |

## 硬约束（做错会超时或误伤）

**① 取书是分钟到小时级的长任务，绝不能等它跑完。**
`book_fetch` / `batch_fetch` 会立即返回。之后用 `app_status` / `task_log` **轮询**进度，一次问一句「现在到哪了」，别在工具调用里挂等。挂等的结果一定是客户端超时，而任务其实还在跑——用户会以为失败了。

**② 两个写操作，只做用户明确要求的那一个。**
- `shelf_add`：会真的往用户的微信读书书架里加书，加完在 App 里就能看到。用户说「搜一下」不等于说「加进书架」。
- `cache_delete`：会删本机已导出的 Markdown 与图片。默认只列清单，**列出来给用户确认过再传 `confirm: true`**。它不影响微信读书里的划线。

**③ `book_fetch` 不是幂等重启。** 同一本书再发起一次是续取，不是重跑。想重跑先跟用户确认。

**④ 本地标记不是微信读书的进度。** `book_mark` 只动本机 `library.json`，用户微信读书里的阅读进度不会变。别把二者说成一回事。

## 常见动作序列

**找一本没读过的书，看要不要读**
```
search_books(q="关键词", scope="store")   # 书城搜
book_detail(book="书名片段")               # 看简介、评分、你的进度
→ 用户说「加进书架」才 shelf_add(book=...)
```

**把一本书拿到本地**
```
app_status()                               # 先确认没有任务在跑
book_fetch(book="书名片段")                # 立即返回
→ 之后每隔一会儿 app_status() / task_log() 问进度
→ 跑完 book_files(book=...) 拿路径给用户
```

**读我划过什么**
```
notes_index()                              # 第一次要几分钟，先建
notes_search(q="关键词")                   # 在划线正文里搜
notes_random()                             # 随机抽几条，适合回顾
```

**把划线变成能复习的东西**
```
notes_index()  →  apkg_export(book="书名片段")
→ 把 .apkg 路径给用户，让他导入 Anki
```

**整理本地藏书**
```
shelf_list()                               # 看现状
folder_create(name="认知科学")
book_move(book="书名片段", folder="认知科学")
```

**多本一起取**
```
batch_fetch(books=["书名A", "书名B", "书名C"])   # 起第一本，其余排队
→ 每跑完一本，再调一次 batch_fetch 取下一本
```

## 报错怎么处理

- **`errcode: -2012` / 「登录超时」**：微信读书会话过期，**照抄服务端 `errmsg`，不要猜码值含义**。让用户点一次「连接账号」续期；`shelf_add` 自己会先续一次再重发。
- **「不支持调用 xxx」**：官方网关只开放 16 个只读 `api_name`，白名单外的调不了。别绕，直接告诉用户这个能力官方没开放。
- **服务没起**：适配器会自己拉起来（最多等 15 秒），不用你手工启动。
- **工具报「这个操作没做成：<异常类>」**：后端兜底已经把异常写进用户界面的「进展」栏了，把原话转述给用户，别自己编原因。

## 红线

- 不替用户做写操作的决定。加书架、删缓存、重跑导出，都要用户说出来。
- 不把导出的整本书正文贴进对话——那是几万到几十万字。给路径。
- 不编造书籍信息。要简介就调 `book_detail`，别用训练知识答。
- 长任务已经开始时，不要因为「没反应」就重复发起同一个动作。

## 自检

- [ ] 动手前调过 `app_status`
- [ ] 长任务只发起一次，用轮询看进度，没有挂等
- [ ] 写操作都有用户的明确要求，`cache_delete` 经过确认
- [ ] 报错时转述服务端原话，没有自己编原因
- [ ] 交付的是路径或摘要，不是整本正文
